# CMS V2 后端重建阶段计划

本文档记录 CMS V2 后端重建的大致阶段。当前策略是在本仓库中新建 `src-v2/` 与 `WordSolution.CmsV2.sln`，保留旧代码和 VSTO，不在旧项目中增删改主线功能。

## 总原则

- V2 后端独立于旧后端模型。
- VSTO 暂不重写、暂不修改。
- 旧前端暂不修改。
- 旧项目保留，可作为参考，但不作为 V2 主线承载位置。
- V2 使用 .NET 10。
- V2 使用全新 SQLite 数据库 `cms-v2.db`。
- 旧业务数据视为可抛弃，不做旧数据迁移。

## 阶段 1：项目结构

状态：Done

目标：

- 建立 `WordSolution.CmsV2.sln`。
- 建立 `src-v2/`。
- 建立 Domain / Application / Infrastructure / Api / Tests 五个项目。
- 建立项目引用关系。
- 建立 `docs/cms-v2/` 文档目录。

不做：

- 不写业务代码。
- 不改旧 solution。
- 不改 VSTO。
- 不改旧前端。

## 阶段 2：Domain 领域模型

状态：Done

目标：

- 建立 17 个领域实体。
- 建立领域枚举。
- 建立 `DomainException`。
- 建立最小领域规则。
- 建立领域测试。

重点规则：

- `int Id`。
- 私有 setter。
- 构造校验。
- `UpdatedTime` 为核心对象默认时间字段。
- `GeneratedFile` 保留 `GeneratedTime`。
- `ContentBlockVersion` 不保存难度、内容类型、题型。
- `TeachingNote` 独立建模。

## 阶段 3：全新 SQLite / EF Core 表结构

状态：Done

目标：

- 引入 EF Core 10 + SQLite。
- 固定本地 `dotnet-ef` 工具版本。
- 建立 `CmsV2DbContext`。
- 建立实体配置。
- 建立设计时工厂。
- 建立初始建库迁移。
- 建立持久化 schema 测试。

重点边界：

- 数据库文件固定为 `cms-v2.db`。
- 不读取 `question-bank.db`。
- 不修改 `question-bank.db`。
- 不迁移旧业务数据。
- 不建立旧表兼容层。

## 阶段 4：仓储与 Unit of Work

状态：Pending

目标：

- 为 17 个核心对象建立仓储落点。
- 明确查询边界和保存边界。
- 建立 Unit of Work 或等价事务入口。
- 建立基础 CRUD 持久化测试。
- 保持多态引用的仓储查询能力。

需要完成：

- 定义仓储接口位置。
- 定义基础查询方法。
- 定义按 `TargetType + TargetId` 查询引用的方法。
- 定义按父子关系读取 Section / AtomicSection / HandoutVersion 编排的方法。
- 定义事务提交入口。
- 补充 SQLite 集成测试。

不做：

- 不做旧数据导入。
- 不做 API。
- 不做前端。
- 不做 DOCX 处理。

## 阶段 5：Application 用例与跨实体规则

状态：Pending
