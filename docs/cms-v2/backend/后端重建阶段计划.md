# CMS V2 后端重建阶段计划

本文档记录 CMS V2 后端重建的大致阶段。当前策略是在本仓库中新建 `src-v2/` 与 `WordSolution.CmsV2.sln`，保留旧代码和 VSTO，不在旧项目中增删改主线功能。

说明：

- 本文档描述的是 V2 后端历史重建阶段。
- 当前全局阶段 1 是“文档清理阶段”，不是这里的后端阶段 1。
- 当前全局阶段 1 不允许修改 `VSTO/`、`Word本地文件操作核心库/` 或 V1 后端项目。

## 总原则

- V2 后端独立于旧后端模型。
- VSTO 暂不重写、暂不修改。
- `Word本地文件操作核心库` 暂不重写、暂不修改。
- 旧前端视为历史实现，不再作为当前主线前端。
- 旧项目保留，可作为参考，但不作为 V2 主线承载位置。
- V2 使用 .NET 10。
- V2 使用全新 SQLite 数据库 `cms-v2.db`。
- 旧业务数据视为可抛弃，不做旧数据迁移。

## 后续待实现：移除引用后的空壳对象清理

状态：Planned / Deferred

触发背景：

- `SectionPage` 删除动作当前优先表达“移除引用”，例如从 Section 移除 AtomicSection、从 AtomicSection 内部移除 ContentBlock。
- 用户期望后续在移除引用后，后端能自动判断目标对象是否只是空壳。
- 如果被移除对象为空壳，并且没有其他引用，后端可以在同一业务用例中继续删除该对象本体。
- 该逻辑涉及引用统计、文件资产、版本、组合关系和删除顺序，存在误删风险，因此不在当前轮实现，先作为后续专项记录。

目标：

- 前端仍只提交“移除引用”动作，不在前端判断对象是否为空。
- Application 层统一封装 `remove reference + optional empty target cleanup` 语义。
- 展示组件仍只 emit 事件，不能直接调用实体删除 API。
- API 返回结果后续应能表达是否只移除了引用，或同时删除了空壳目标。

建议实现方式：

- 在 Application 层新增或扩展一个清理策略，例如 `EmptyTargetCleanupPolicy`。
- `SectionItem`、`AtomicSectionItem`、`ContentBlockRelation` 的移除用例复用同一套清理判断。
- 物理删除实体前必须先检查：
  - 是否仍被其他 Section / AtomicSection / ContentBlock / HandoutVersion 引用。
  - 是否存在 `ContentBlockVersion`、DOCX、HTML、PlainText 等内容资产。
  - 是否存在 child relation 或内部 item。
- 默认行为仍应是保守的：任何无法确认为空的对象都只移除引用，不删除本体。

候选规则：

- `ContentBlock`：只有在无版本、无内容资产、无 child relation、无其他引用时，才允许作为空壳清理。
- `AtomicSection`：只有在无 `AtomicSectionItem`、无其他 `SectionItem` 引用时，才允许作为空壳清理。
- `CompositeBlock` 本质仍是 `ContentBlock`，按 `ContentBlock` 清理规则处理。
- 删除 `CompositeBlock` 内部 child relation 不应自动删除 parent `CompositeBlock`。

测试优先级：

- 移除空 `ContentBlock` 引用时，同时删除空壳实体。
- 移除已有 DOCX / version / plain text 的 `ContentBlock` 引用时，只移除引用。
- 移除仍被其他结构引用的对象时，只移除当前引用。
- 移除空 `AtomicSection` 引用时，同时删除空壳实体。
- 移除非空 `AtomicSection` 引用时，只移除引用。
- `CompositeBlock` child relation 移除不误删 parent。

本阶段明确不做：

- 当前轮实现。
- 数据库结构调整。
- 前端自行判断空壳。
- 绕过引用检查的实体删除。
- 删除已有版本、DOCX、HTML、PlainText 或被其他结构引用的内容资产。
## 当前补充：SectionItem 批量升级为 AtomicSection

CMS V2 后端新增专用事务能力：

```text
POST /api/cms-v2/sections/{sectionId}/items/wrap-as-atomic-section
```

该能力用于把 Section 中多个连续的顶层 ContentBlock SectionItem 包装为一个新的 AtomicSection。

后端规则：

- 必须由 Application 用例在一个事务中完成，不允许前端串联多个 API。
- 第一版只允许连续的顶层 SectionItem。
- 选中项必须全部属于当前 Section。
- 选中项目标必须是 ContentBlock；CompositeBlock 本质仍是 ContentBlock，因此允许。
- 已有 AtomicSection 不允许参与升级。
- 新 AtomicSection 默认 Draft。
- 新插入的 SectionItem 默认 Active。
- 原 SectionItem 的 ReferenceMode、LockedContentBlockVersionId、TitleOverride、Note 必须转移到 AtomicSectionItem。
- 删除原 SectionItem 只删除引用，不删除源 ContentBlock、DOCX、版本或组合关系。
- 新 AtomicSection SectionItem 出现在第一个被选中块的原始位置。
- 同级 SectionItem SortOrder 在事务内重新规整。
- 任一步失败必须整体回滚，不留下半成品 AtomicSection 或 AtomicSectionItem。

测试要求：

- 覆盖成功升级、非连续失败、包含 AtomicSection 失败、跨 Section 失败、空列表/单项失败、锁定版本转移和事务回滚。
