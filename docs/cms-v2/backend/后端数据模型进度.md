讲义展开规则：

```text
HandoutVersionItem.TargetType = ContentBlock
  使用该 ContentBlock 当前版本。

HandoutVersionItem.TargetType = SectionVariant
  展开 SectionVariantItems。
  再逐个解析 SectionItem。

HandoutVersionItem.TargetType = AtomicSection
  直接引用 AtomicSection。
  整体展开 AtomicSectionItems。
  不创建 SectionItem。
  不反向修改 Section。

SectionItem.TargetType = ContentBlock
  ReferenceMode = FollowLatest 时使用当前版本。
  ReferenceMode = LockedVersion 时使用 LockedContentBlockVersionId。

SectionItem.TargetType = AtomicSection
  展开 AtomicSectionItems。
  AtomicSectionItem 按自身 ReferenceMode 解析 ContentBlockVersion。

ContentBlockRelation
  先输出父块自身版本。
  再按 SortOrder + Id 递归输出子块。
  子块按 relation 的 ReferenceMode 解析版本。
  生成阶段再次检测循环引用。
  最大展开深度固定为 10。
```

版本清单：

```text
GeneratedFile.VersionManifestJson 使用 camelCase JSON。
schemaVersion 固定为 1。
generatedTime 记录本次生成时间。
outputFormId 记录输出形式。
handoutVersionId 记录讲义版本。
sources 按最终拼接顺序记录 ContentBlockId、ContentBlockVersionId、VersionNumber、DocxPath。
```

失败处理：

```text
OutputForm 不存在时抛 CmsV2ApplicationException。
OutputFormat = Pdf / WordAndPdf 时抛 CmsV2ApplicationException。
HandoutVersion 不存在时抛 CmsV2ApplicationException。
OutputTemplate 不存在或模板 DOCX 缺失时抛 CmsV2ApplicationException。
ContentBlock 当前版本缺失时抛 CmsV2ApplicationException。
锁定版本不存在或不属于目标 ContentBlock 时抛 CmsV2ApplicationException。
内容块 DOCX 文件缺失时抛 CmsV2ApplicationException。
ContentBlockRelation 出现循环或深度超过 10 时抛 CmsV2ApplicationException。
失败时不写 GeneratedFile。
失败时尽量删除本次生成的半成品 DOCX。
```

## 当前进度校准：SectionVariant

本节只记录进度差异，不表示以下待办已经实现。

已确认的现状：

- `SectionVariant` 领域模型已经存在。
- `SectionVariantItem` 领域模型已经存在。
- `SectionVariantItem` 通过 `SectionItemId` 引用 `SectionItem`。
- `AtomicSection` 已经具备 `Difficulty` 字段。
- `SectionItem.TargetType` 当前只包含 `ContentBlock` 与 `AtomicSection`。
- `CompositeBlock` 不是后端目标类型，它只是组类型 `ContentBlock` 的前端展示组件。

仍需补齐的能力：

- `POST /api/cms-v2/section-variants/selection-preview`。
- 创建 `SectionVariant` 时一次性写入 `selectedSectionItemIds`。
- 后端在事务中创建 `SectionVariant` 与 `SectionVariantItem`。
- 同一个 `Section` 下 `SectionVariant.Title` 唯一校验。
- 创建请求不再要求前端提交 `Status` 与 `SortOrder`。
- 前端第一版只提交顶层 `SectionItemId`，不提交 `ContentBlockId`、`AtomicSectionId` 或 `flowItemId`。

文档已关闭的旧疑问：

- `AtomicSection` 难度字段并非缺口，已经存在。
- `SectionVariant` 第一版不选择 `AtomicSectionItem`。
- `SectionVariant` 第一版不选择 `CompositeBlock` 子 relation。
- `SectionVariant` 创建入口不放在 Toolbar、Workspace、Inspector 或 TeachingStructureTree。
