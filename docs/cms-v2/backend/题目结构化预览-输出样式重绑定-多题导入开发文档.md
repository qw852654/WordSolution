# CMS V2 题目结构化预览、输出样式重绑定与多题导入开发文档

本文件记录 `ContentBlock` 题目内容结构化、结构化 HTML 预览、讲义 Word 输出样式重绑定，以及 Word 多题导入切割流程的正式开发约定。

本能力线只属于 CMS V2 主线：

- 后端只修改 `src-v2/WordSolution.CmsV2.*`。
- 前端只修改 `frontend-v2`。
- 不修改 V1 前端、V1 后端、`VSTO/`、`Word本地文件操作核心库/`。
- 不复用 `/api/题库实例/...`。
- 不把临时多题导入建模为普通 `ContentBlock` 编辑会话。

## 0.1 原始规格全量校准结论

本节用于把原始规格、正式开发文档和当前实现状态一次性对齐。后续判断“是否完成”时，不能只看某个接口或组件是否存在，必须按下表逐条验收。

| 能力链路 | 原始规格要求 | 当前实现状态 | 校准结论 |
|---|---|---|---|
| 题目结构模型 | 一个正式题目仍是一个 `ContentBlock`、一个当前 `ContentBlockVersion`、一个正式单题 docx、一个结构化 HTML、若干 `ContentBlockVersionPart`。不得把题干、答案、解析拆成多个 `ContentBlock`。 | Phase 1 已完成：`ContentBlockVersionPart`、`PartParseStatus / PartParseMessage`、仓储、迁移、API 和测试均已落地；非 `Question` 默认 `NotApplicable`，不生成 Part。 | 当前实现与本口径一致。结构化解析阶段缺 Stem 会失败，非 Question 不强制结构化，历史“组类型也生成 Part”的偏差已关闭。 |
| Word Part 解析 | 每个段落独立按样式映射到 `Stem / Answer / Analysis / Hint / Other`；空段落保留；表格按内部段落归类，混合 Part 表格进入 `Other` 并 warning。 | Phase 1 已完成：段落、空段落、未知样式、混合表格 warning、Aspose 评估段落过滤和缺 Stem 失败均有测试覆盖。 | 当前实现按固定 Part 语义解析；`Other` 只作为异常/未识别内容承载，不作为题干兜底。 |
| 结构化 HTML 预览 | 每个 `PartType` 最多一个 `<section data-question-part="...">`，按 `Stem / Answer / Analysis / Hint / Other` 展示；前端默认显示全部，答案/解析/提示可折叠。 | Phase 1/4 已完成：后端按固定系统顺序输出结构化 HTML，前端 `ContentBlockDisplay` 消费 `data-question-part` 和 Part 元数据。 | 当前实现与本口径一致；前端不解析 Word 样式。 |
| 输出 Word 样式重绑定 | 只在输出副本中重绑定题干首个有效 Stem 段落样式；不改源 docx，不重排 Part，不隐藏答案/解析。输出前必须检查模板样式。 | Phase 2 已完成：输出生成使用 occurrence 输出样式，生成前检查模板样式，并已提供 `POST /api/cms-v2/output-forms/{id}/validate-word-generation`。Phase 5 补充确认导入候选正式 docx 中性化也只识别 Stem。 | 当前实现与本口径一致；缺 OutputStyle / 缺模板样式是阻断错误，缺 Stem 返回结构化可跳过问题，生成时跳过该 `ContentBlock`，不插入 Word，也不写入 `GeneratedFile.VersionManifestJson.sources`。 |
| 输出上下文 | `AtomicSectionItem.TeachingRole` 决定 AS 内题目的输出样式；Section 顶层、直接 Handout Question、ContentBlockRelation 子题按练习题输出。 | Phase 2 已完成：后端已有 `QuestionOutputStyleOptions`，AS 内 item 走 `TeachingRole`，直接题和子题默认 Practice。 | 当前实现与本口径一致；不得从 Word 样式推断 `TeachingRole`。 |
| 多题导入会话 | 用户点击批量导入后，系统创建并打开临时 Word；用户粘贴/整理并保存关闭；后端检测关闭后切割；前端轮询到 `ReadyForReview`；用户批量勾选确认后一次性正式入库。 | Phase 3/4 已完成：后端使用临时 Word session、状态机、关闭检测、candidate 查询、reopen、cancel 和批量 confirm；前端改接 JSON session API 并轮询状态。 | 当前实现与本口径一致。历史 multipart 上传、创建 session 后立即切割、逐候选确认均为已修正偏差。 |
| 多题导入面板 | 面板展示会话状态、打开/重新打开 Word、候选题批量勾选、候选 HTML 预览、标题输入、警告/错误；不提供本地 docx 上传作为主流程。 | Phase 4 已完成：`QuestionImportDialog` 只发出 `startSession / reopenSession / confirmCandidates / cancelSession / close` 事件，不包含文件上传主入口或单候选确认按钮。 | 当前实现与本口径一致；组件只展示工作流和候选确认，不直接创建正式对象。 |
| 多题导入正式入库 | 批量确认时一次事务创建多个 `ContentBlock`、版本、Part、正式单题 docx、HTML/txt，并按 `InsertQuestionContext` 创建 `SectionItem` 或 `AtomicSectionItem`。 | Phase 3 已完成：`ConfirmAsync` 批量处理候选，按上下文创建顶层 `SectionItem` 或 `AtomicSectionItem`，返回首个新增节点定位信息。 | 当前实现与本口径一致；确认前不写正式数据库或正式 `content-blocks/` 资产目录。 |
| 临时简化登记 | 任何为了跑通链路的临时简化必须立即登记，并在人工验收前补齐。 | Phase 5 校准：上传式导入、逐候选确认、缺少 reopen/关闭检测等历史简化已关闭。 | 后续不得再把这些历史偏差作为当前实现目标或验收口径。 |

## 1. 核心目标

早期 `ContentBlockVersion` 只有整篇 docx、整篇 HTML 预览和纯文本。Phase 1 已补齐题目结构层：

```text
ContentBlock
  ContentBlockVersion
    docx
    html
    plainText
    ContentBlockVersionPart[]
```

新增能力后，一个正式题目仍然是：

```text
一个 ContentBlock
一个当前 ContentBlockVersion
一个正式单题 docx
一个结构化 HTML 预览
若干 ContentBlockVersionPart 元数据
```

禁止把普通题目物理拆成：

```text
Question ContentBlock
Answer ContentBlock
Analysis ContentBlock
```

`ContentBlockType.Answer` 和 `ContentBlockType.Analysis` 仍保留给真正独立的答案材料或长解析内容，不用于强制拆分每道普通题。

## 2. 内容结构 Part

### 2.1 ContentBlockPartType

新增结构枚举：

```csharp
public enum ContentBlockPartType
{
    Stem = 1,
    Answer = 2,
    Analysis = 3,
    Hint = 4,
    Other = 5
}
```

`PartType` 表示题目内容结构，不表示教学身份，也不表示题目在讲义中的输出角色。

### 2.2 Part 解析状态

`ContentBlockVersion` 需要补充：

```text
PartParseStatus
PartParseMessage
```

建议枚举：

```csharp
public enum ContentBlockPartParseStatus
{
    NotApplicable = 0,
    Parsed = 1,
    ParsedWithWarnings = 2,
    Failed = 3
}
```

语义：

- `NotApplicable`：该内容块不需要题目结构化，例如普通说明、方法总结。
- `Parsed`：已解析出结构化 Part，且无警告。
- `ParsedWithWarnings`：已解析出结构化 Part，但存在未知样式、混合表格等警告。
- `Failed`：解析失败，不应伪装为结构化成功。

说明：

- 原始规格曾使用 `Success / Warning` 命名，当前实现用 `Parsed / ParsedWithWarnings` 承载同一语义，可以保留。
- 原始规格提到的 `NotParsed` 表示“尚未解析”。当前正式版本创建链路会立即解析；如果后续出现异步解析或空白题目占位，再补 `NotParsed` 或等价状态，不得用 `Parsed` 伪装未解析。
- `Question` 类型如果没有形成有效 `Stem`，不得返回 `Parsed`；必须进入 `Failed` 并显示原因。

### 2.3 ContentBlockVersionPart

新增实体目标：

```csharp
public sealed class ContentBlockVersionPart
{
    public int Id { get; private set; }
    public int ContentBlockVersionId { get; private set; }
    public ContentBlockPartType PartType { get; private set; }
    public int SortOrder { get; private set; }
    public string? PlainText { get; private set; }
    public string? SourceStyleNamesJson { get; private set; }
    public string? WarningMessage { get; private set; }
}
```

约束：

- `(ContentBlockVersionId, PartType)` 唯一。
- `SortOrder >= 0`。
- `ContentBlockVersionPart` 不保存 HTML。
- Part HTML 由 docx 转换过程生成，Part 元数据只保存结构、纯文本、样式来源和警告。

## 3. Word 样式到 PartType 的映射

第一版采用用户确认的样式名精确匹配规则：

```text
Trim 后精确匹配
大小写不敏感
```

当前用户已确认配置：

| 配置项 | 样式名 |
|---|---|
| Stem 样式名集合 | `例题`、`典型例题`、`变式`、`提高`、`练习题` |
| Answer 样式名集合 | `答案` |
| Analysis 样式名集合 | `解析` |
| Hint 样式名集合 | `教学讲解内容` |
| 普通正文样式名集合 | `正文` |

这些值来自用户提供并确认的个人 Word 样式配置，不是 Codex 猜测默认值。后续实现可以保留这些配置，但文档、Options 和测试说明必须持续表达为“用户已确认配置”。

映射规则：

```text
Stem 样式 / 普通正文样式 -> Stem
Answer 样式              -> Answer
Analysis 样式            -> Analysis
Hint 样式                -> Hint
无法识别的其他样式        -> Other
```

重要边界：

- Word 样式只表达内容结构，不决定 `ContentBlock` 的教学身份。
- 不得根据 Word 样式覆盖 `ContentBlock.BlockType`、`AtomicSectionTeachingRole` 或 `SectionVariant` 选择结果。
- 每个段落根据自己的段落样式独立判断 `PartType`。
- 不采用“遇到答案样式后，后续所有正文都属于答案”的状态机规则。

## 4. 空段落和非段落内容

空段落不能丢弃。空段落按自己的段落样式归入对应 Part：

```text
空的答案样式段落 -> Answer
空的解析样式段落 -> Analysis
空的正文样式段落 -> Stem
空的未知样式段落 -> Other
```

原因：

- 空段落可能承载 Word 排版间距。
- 丢失空段落会改变 HTML 预览和最终单题 docx 版式。

非段落节点处理：

- 行内图片、公式等随所在 `Paragraph` 一起归类。
- 顶层表格需要检查内部段落样式。
- 如果一个表格内部有效段落都属于同一 Part，则整个表格归入该 Part。
- 如果同一个表格内部混有多个 PartType，第一版不强行拆表，整个表格归入 `Other`，并记录 Warning。
- 不得为了“解析成功”静默丢弃表格、图片、公式或嵌入对象。

## 5. 结构化 HTML 预览

### 5.1 HTML 输出结构

结构化 HTML 中，一个 `PartType` 最多输出一个 section：

```html
<section data-question-part="Stem">...</section>
<section data-question-part="Answer">...</section>
<section data-question-part="Analysis">...</section>
<section data-question-part="Hint">...</section>
<section data-question-part="Other">...</section>
```

规则：

- `data-question-part` 由系统生成，不来自源 Word。
- 一个 PartType 最多一个 section。
- 如果同一 PartType 在源 Word 中多次、不连续出现，HTML 仍聚合为一个 section，并通过内部顺序保留内容顺序。
- section 输出顺序固定为 `Stem / Answer / Analysis / Hint / Other`，不得按源文档中 Part 首次出现顺序输出。
- head 中样式和资源定义只保留一份。
- 图片可继续使用 base64，第一版不引入独立资源打包。

### 5.2 非题目内容块

对不需要结构化的内容块：

- 可以继续生成普通整块 HTML。
- `PartParseStatus = NotApplicable`。
- 不创建 `ContentBlockVersionPart`。
- 前端按普通 `ContentBlockDisplay` 展示，不显示题目结构折叠控件。

范围边界：

- 原始规格只强制 `ContentBlockType.Question` 生成 `Stem / Answer / Analysis / Hint / Other` 结构。
- `ExampleGroup / ExerciseGroup / VariantGroup` 第一版仍按组类型 `ContentBlock` / `CompositeBlock` 展示，不因本能力线默认成为结构化 Question Part。
- 如果后续再次出现为这些组类型生成 Part 的实现，应登记为回归偏差，改回 `NotApplicable` 或另行等待用户确认。
- 不得借题目结构化预览重新强化旧 Group / CompositeBlock 作为 AtomicSectionPanel 的替代路径。

### 5.3 前端展示目标

`ContentBlockDisplay` 后续需要根据版本结构状态决定展示方式：

- `Parsed / ParsedWithWarnings`：显示结构化题目预览。
- `Failed`：显示解析失败信息，并保留普通预览或错误入口。
- `NotApplicable`：显示普通内容预览。
- 无 docx / 无 HTML：保持当前“没有 Word 文档，点击 Word 编辑创建”的提示。

结构化预览第一版支持：

- 题干常显。
- 答案、解析、提示可折叠。
- `Other` 用警告弱提示展示。
- 组件只展示和 emit，不直接调用 API。

## 6. 输出 Word 样式重绑定

### 6.1 核心原则

讲义输出时，不依赖源 `ContentBlock` docx 自带的题干首段样式。

输出系统应根据题目在当前讲义中的出现上下文，决定题干首个有效 Stem 段落使用哪个输出样式。

只在输出副本中重绑定样式：

- 不修改源 `ContentBlock` docx。
- 不修改 `ContentBlockVersionPart`。
- 不修改答案、解析、提示段落样式。
- 不修改题干后续普通段落，第一版只处理题干首个有效 Stem 段落。
- 不得把 `Other` 当作 Stem 的兜底候选。找不到有效 Stem 段落时，应在预检查中返回 `MissingQuestionStem`，生成阶段跳过该 `ContentBlock`，不插入 Word，也不写入 manifest sources。

### 6.2 输出样式配置

当前已确认：

| 出现上下文 | 输出题干首段样式 |
|---|---|
| Example | `例题` |
| Variant | `变式` |
| Practice | `练习题` |
| Homework | `练习题` |
| Unclassified | `练习题` |
| 直接作为 Handout Question 输出 | `练习题` |
| ContentBlockRelation 子题输出 | `练习题` |

正式单题 docx 的中性题干首段样式：

```text
正文
```

### 6.3 输出模板样式预检查

生成 Word 前必须打开 `OutputTemplate`，检查所有本次输出需要的目标样式是否存在。

第一版至少检查：

- `例题`
- `变式`
- `练习题`

如果输出内容不需要某个样式，可以不要求模板包含该样式。

缺失样式时：

- 不生成 Word。
- 不创建 `GeneratedFile`。
- 返回明确错误信息。
- 错误中包含缺少哪个样式、为什么需要该样式。

禁止：

- 缺样式时保持原样继续生成。
- 前端写死样式名绕过后端校验。
- 后端使用未确认的默认样式名。

独立预检 API：

- 当前已提供 `POST /api/cms-v2/output-forms/{id}/validate-word-generation`，用于在生成前返回结构化问题列表。
- 如果后续退化为只在 `generate-word` 内部抛错，必须登记为回归偏差；生成时抛错可以保护生成结果，但不能替代前端可主动调用的预检链路。
- 生成 API 仍必须复用同一校验，避免预检通过但生成阶段绕过校验。
- 问题返回至少包含缺失样式名、需要该样式的对象类型、对象 ID、出现上下文和用户可见原因。

### 6.4 重绑定时机

重绑定发生在内容导入输出文档之后、保存生成文件之前。

推荐流程：

```text
加载 OutputTemplate
解析 HandoutVersion 内容
解析每个 ContentBlock occurrence 的教学上下文
预检查模板目标样式
导入源 docx 内容到输出文档副本
定位首个有效 Stem 段落
把该段落样式设置为 OutputTemplate 中的目标样式
保存 GeneratedFile
```

回归保护：

- 保留现有结构标题输出逻辑，`TeachingTopic / Section / AtomicSection` 的 Heading 不因题干样式重绑定被移除。
- 保留当前正文拼接、源 DOCX 页眉页脚清理、模板页眉页脚保留、编号重建、`GeneratedFile` 成功写入、失败不写入和半成品清理逻辑。
- 题干样式重绑定只作用于输出副本中的首个有效 `Stem` 段落；源 docx、Part 元数据、答案、解析、提示和后续题干段落保持不变。

## 7. Word 多题导入切割临时流程

### 7.1 目标工作流

多题导入第一版不是“选择一个已有 docx 文件上传并立即切割”。

正确工作流为：

```text
用户在任意“可插入题目”的位置点击批量导入
↓
系统创建临时 Word
↓
自动打开 Word
↓
用户粘贴 / 整理网上题目
↓
用户保存并关闭 Word
↓
后端检测文件已关闭
↓
自动切割
↓
自动生成候选题临时 HTML
↓
前端轮询得到 ReadyForReview
↓
前端打开确认页面
↓
用户勾选并确认
↓
后端一次性批量正式入库
↓
刷新 Section 并定位新题
↓
立即清理临时数据
```

禁止把该流程简化为：

```text
选择并上传一个 .docx 文件
立即返回候选题
逐个候选题单独确认入库
```

如果后续实现再次采用上述简化，必须登记为回归偏差，并在进入人工验收前替换为临时 Word 会话模式。

### 7.2 题目开始样式

多题切割依赖“新题开始样式”。

当前已确认：

```text
QuestionStartStyleNames = 例题、典型例题、变式、提高、练习题
```

这些样式可以与 Stem 样式集合重叠，但必须作为独立配置保存和使用。

第一版切割规则：

- 每次遇到 `QuestionStartStyleNames` 中的段落样式，视为一道新题开始。
- 从一个题目开始样式到下一个题目开始样式前，属于同一道题。
- 最后一题从最后一个题目开始样式到文档结尾。
- 第一个题目开始样式前的内容按用户已确认规则丢弃；不得写入候选题，也不得进入正式内容块。

风险提示：

- 如果题干后续段落也使用 `例题 / 典型例题 / 变式 / 提高 / 练习题`，会被识别为新题开始。
- 用户需要在源 Word 中使用样式约定保证新题开始样式只出现在题目首段。

### 7.3 临时会话

多题导入使用临时会话，不建正式数据库表。

临时目录建议固定为：

```text
edit-sessions/question-imports/{sessionId}
```

禁止把临时多题导入建模为：

- 普通 `ContentBlock` 编辑会话。
- 正式 `ContentBlockVersion`。
- 正式 `ContentBlockVersionPart`。

临时会话应保存：

- 系统创建并自动打开的临时源 docx。
- 切割候选 docx。
- 每个候选的结构化预览。
- 每个候选的解析状态和警告。
- 用户确认前的临时元数据。
- 会话状态：`Created / Opening / Editing / Parsing / ReadyForReview / Importing / Imported / Failed / Cancelled / Expired`。

取消会话或会话过期时，删除临时文件，不留下正式内容块。

前端必须轮询会话状态。Word 文件关闭后，后端自动进入切割流程，不得要求用户额外点击“解析”。

### 7.4 确认导入

切割完成不等于正式入库。只有用户在确认页面勾选并确认后，才允许创建正式内容。

确认前禁止：

- 写入正式数据库中的 `ContentBlock`、`ContentBlockVersion`、`ContentBlockVersionPart`、`SectionItem` 或 `AtomicSectionItem`。
- 把候选题 docx / HTML / text 写入正式 `content-blocks/` 资产目录。
- 创建正式 `ImportSession / ImportCandidate` 业务表或把临时会话伪装成正式内容资产。

确认页第一版显示：

- 勾选框。
- 候选序号。
- 标题输入框，默认空。
- 结构解析状态。
- 是否包含 `Stem / Answer / Analysis / Hint`。
- 临时 HTML 预览。
- 结构警告 / 错误。

确认页允许：

- 取消勾选某道题。
- 修改标题。
- 取消整次导入。
- 确认已勾选题目。

确认页不允许：

- 手工拆题。
- 手工合并。
- 编辑正文。
- 逐题修改 `TeachingRole`。
- 逐题修改 `Difficulty`。
- 编辑标签。
- 拖拽候选顺序。

用户确认一批候选成为正式题目时，每道已勾选候选执行：

1. 创建 `ContentBlock`。
2. 创建正式 `ContentBlockVersion`。
3. 复制候选 docx 为正式单题 docx。
4. 将正式单题 docx 的题干首个有效 Stem 段落样式中性化为 `正文`。
5. 生成结构化 HTML。
6. 创建 `ContentBlockVersionPart`。
7. 设置当前版本。
8. 根据插入上下文创建 `SectionItem` 或 `AtomicSectionItem`。

正式入库必须一次事务全成功或全失败。任何一步失败都必须回滚，不留下半成品 `ContentBlock`、版本、Part、`SectionItem` 或 `AtomicSectionItem`。

失败时已经写入正式文件系统的 docx / HTML / text 必须按现有 best-effort 清理原则删除；数据库不得保留部分成功记录。临时会话文件可保留用于错误查看，并按 1 小时过期规则清理。

每道已勾选候选的默认正式内容语义：

```text
ContentBlock.BlockType = Question
ContentBlock.QuestionType = Unset
ContentBlock.Title = 用户输入值或空字符串
ContentBlock.Difficulty = InsertQuestionContext.DefaultDifficulty
```

正式 `ContentBlock.Title` 允许为空。前端可以显示“候选题 1 / 候选题 2”，但不得把该显示序号写入正式标题。

### 7.5 插入上下文

多题导入入口不限于 Section 顶层。

所有需要插入题目的地方都应通过统一插入上下文表达：

```ts
type InsertQuestionContext = {
  sectionId: number
  atomicSectionId?: number | null
  atomicSectionPanelId?: number | null
  afterAtomicSectionItemId?: number | null
  afterSectionItemId?: number | null
  defaultTeachingRole: AtomicSectionTeachingRole
  defaultDifficulty: Difficulty
}
```

规则：

```text
有难度 Panel:
  Role = Panel.TeachingRole
  Difficulty = Panel.Difficulty
  PanelId = 当前 Panel

无难度 Panel:
  Role = Panel.TeachingRole
  Difficulty = Unset
  PanelId = 当前 Panel

未归入区域 / AtomicSection 顶部:
  Role = Unclassified
  Difficulty = Unset
  PanelId = null

Section 顶层题目入口:
  默认输出角色最终为 Practice
  ContentBlock.Difficulty 由入口默认规则决定
```

Codex 实现前必须确认当前 UI 中哪些插入点属于第一版批量导入范围。

### 7.6 API 目标语义

最终 API 语义应支持临时 Word 会话，而不是文件上传式一次性切割。

建议目标接口：

```text
POST /api/cms-v2/question-import-sessions
GET  /api/cms-v2/question-import-sessions/{sessionId}
GET  /api/cms-v2/question-import-sessions/{sessionId}/candidates
POST /api/cms-v2/question-import-sessions/{sessionId}/confirm
POST /api/cms-v2/question-import-sessions/{sessionId}/cancel
POST /api/cms-v2/question-import-sessions/{sessionId}/reopen
```

创建请求包含：

```ts
type CreateQuestionImportSessionRequest = {
  context: InsertQuestionContext
  openWord: boolean
}
```

确认请求：

```ts
type ConfirmQuestionImportRequest = {
  candidates: Array<{
    candidateId: string
    selected: boolean
    title: string
  }>
}
```

响应必须包含创建的：

```text
ContentBlockIds
ContentBlockVersionIds
AtomicSectionItemIds / SectionItemIds
首个新增节点定位信息
```

### 7.7 历史偏差关闭记录

以下偏差曾存在于早期实现中，但 Phase 3 / Phase 4 已完成收口。后续不得再把这些旧行为当作当前主流程：

1. 历史偏差：前端 `QuestionImportDialog` 要求选择并上传 `.docx`。当前已改为临时 Word session 启动、状态展示、候选确认。
2. 历史偏差：后端 `POST /question-import-sessions` 读取 multipart 文件并立即切割候选题。当前已改为 JSON 创建 session，由系统创建临时 Word。
3. 历史偏差：session 缺少完整状态机。当前已具备 `Created / Opening / Editing / Parsing / ReadyForReview / Importing / Imported / Failed / Cancelled / Expired`。
4. 历史偏差：没有创建临时 Word 并由后端本地策略自动打开。当前已通过 `IQuestionImportSessionLauncher` 抽象并落地本地实现。
5. 历史偏差：没有 Word 关闭检测后自动切割。当前已通过 `IQuestionImportDocumentCloseChecker` 检测关闭并切割候选。
6. 历史偏差：单个候选逐个确认。当前已改为批量确认请求。
7. 历史偏差：确认候选不负责插入上下文。当前 `InsertQuestionContext` 已贯穿创建 session 与批量确认，支持创建顶层 `SectionItem` 或 `AtomicSectionItem`。
8. 历史偏差：缺少 `reopen` / 返回 Word 修正样式能力。当前已提供 reopen API 和前端入口。

当前仍然明确的边界：

- `AtomicSectionPanel` 内的导入入口已作为正式 UI 接入，仍复用 `QuestionImportDialog` 和 `InsertQuestionContext`。
- 后端必须校验 `AtomicSectionPanelId` 指向的 panel 属于指定 `AtomicSection`，且该 `AtomicSection` 属于指定 `Section`。
- 确认导入后创建归属该 panel 的 `AtomicSectionItem`，默认使用 panel 的 `TeachingRole` 与 `Difficulty`。
- 确认前仍不得写正式数据库或正式 `content-blocks/` 资产目录。

## 8. 配置落点

第一版不建立数据库样式配置表。

建议先在后端应用层建立明确的配置对象或 Options：

```text
QuestionPartStyleOptions
QuestionOutputStyleOptions
QuestionImportStyleOptions
```

这些 Options 由代码配置或应用配置文件提供。样式名不得散落在解析器、生成器或 API endpoint 中。

## 9. 阶段计划

### Phase 1：正式开发文档更新

已完成后才能进入实现。

内容：

- 记录用户确认的样式映射。
- 记录 Part 模型。
- 记录结构化 HTML。
- 记录输出样式重绑定。
- 记录多题导入临时流程。
- 记录测试和验收边界。

### Phase 2：Domain / Persistence

目标：

- 新增 `ContentBlockPartType`。
- 新增 `ContentBlockPartParseStatus`。
- 新增 `ContentBlockVersionPart`。
- 扩展 `ContentBlockVersion`。
- 新增仓储入口。
- 新增 EF 配置和迁移。

### Phase 3：Word Part Parser 与结构化 HTML

目标：

- 扩展 `IContentBlockDocumentProcessor` 或新增专用契约。
- 按样式解析 Part。
- 生成 `ContentBlockVersionPart`。
- 生成带 `data-question-part` 的 HTML。
- 保留空段落、图片、公式和表格。

### Phase 4：前端结构化预览

目标：

- 先在 `ComponentLab` 验收结构化预览组件。
- 再接入 `SectionPage` / `HandoutPage` 的 `ContentBlockDisplay`。
- 普通内容块继续使用普通预览。

### Phase 5：输出 Word 样式重绑定

目标：

- 输出前检查模板样式。
- 根据 occurrence 计算目标样式。
- 只重绑定题干首个有效 Stem 段落。
- 缺样式时清晰报错，不生成文件。

### Phase 6：临时多题导入后端

目标：

- 创建临时多题导入会话。
- 在临时目录中创建源 Word。
- 自动打开临时 Word。
- 轮询检测 Word 是否已关闭。
- 关闭后按 `QuestionStartStyleNames` 自动切割候选。
- 生成候选结构化预览。
- 返回会话状态、候选状态和警告。
- 支持取消、过期清理和重新打开临时 Word。

### Phase 7：多题导入前端

目标：

- 在可插入题目的上下文中启动多题导入会话。
- 展示会话状态。
- 前端轮询到 `ReadyForReview` 后打开确认页面。
- 候选列表。
- 候选预览。
- 候选勾选。
- 标题填写。
- 批量确认导入。
- 失败/警告展示。

### Phase 8：正式导入收口

目标：

- 确认候选后一次性创建正式 `ContentBlock`。
- 生成正式单题 docx。
- 中性化题干首段样式为 `正文`。
- 创建正式 Part 元数据。
- 根据 `InsertQuestionContext` 创建 `SectionItem` 或 `AtomicSectionItem`。
- 全成功后刷新 Section 并定位首个新增题目。
- 任一步失败时整体回滚并保留错误信息。

### Phase 9：自动化验证

必须覆盖：

- 样式匹配大小写不敏感。
- 空段落保留。
- 表格混合 Part 归入 Other 并产生 warning。
- 结构化 HTML 包含正确 `data-question-part`。
- 输出模板缺样式时报错。
- 输出题干首段样式按 occurrence 重绑定。
- 多题切割首题前内容丢弃。
- 导入失败不留下半成品。

### Phase 10：人工验收

人工验收场景：

- 单题 Word 中含题干、答案、解析、提示。
- 多段答案、多段解析。
- 空段落和公式图片。
- 表格单一 Part 和混合 Part。
- 多题 Word 导入三题以上。
- 讲义输出中同一题作为例题、变式、练习分别出现。
- 删除模板中的某个目标样式后生成失败并显示缺失样式。

## 10. 当前禁止事项

本能力线第一版禁止：

- 根据 Word 样式推断 `TeachingRole`。
- 把答案、解析拆成独立 `ContentBlock`。
- 丢弃空段落。
- 静默忽略未知样式。
- 缺少模板样式时继续生成 Word。
- 在前端写死输出样式名。
- 在 V1 项目中补实现。
- 修改 `VSTO/` 或 `Word本地文件操作核心库/`。
- 把临时多题导入会话写成正式持久化模型。
