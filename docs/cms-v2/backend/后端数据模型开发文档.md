# CMS V2 后端数据模型开发文档

本文档记录 CMS V2 后端数据模型的目标对象、对象职责、字段、关系、约束、数据库表结构命名和分层落点。

当前已完成范围：

- V2 后端项目骨架。
- Domain 层领域对象、枚举、领域异常和最小领域规则。
- Infrastructure 层全新 EF Core 10 + SQLite 表结构、`CmsV2DbContext`、实体配置和初始建库迁移。
- Domain 层仓储契约与 `ICmsV2UnitOfWork`。
- Infrastructure 层 EF Core 仓储实现与 `EfCmsV2UnitOfWork`。
- Application 层用例、命令 DTO、应用异常和跨实体规则。
- V2 文件资产路径策略、内容块 DOCX 文件存储、HTML 预览生成和 PlainText 提取。
- Application 层内容块文档用例。
- 讲义 DOCX 生成链路、模板套用、内容块递归展开、`GeneratedFile` 写入和版本清单记录。
- V2 本地 HTTP API、依赖注入组合根、启动迁移、异常处理和最小可用端点。

当前未完成范围：

- PDF / WordAndPdf 输出。
- 变量替换与学生版 / 教师版条件过滤。
- 前端。
- 旧数据迁移。

## 2. 数据库边界

V2 使用独立 SQLite 数据库：

```text
cms-v2.db
```

明确不做：

```text
不读取 question-bank.db
不修改 question-bank.db
不迁移旧业务数据
不建立旧 CMS 表结构兼容层
不实现旧数据导入工具
```

`CmsV2DatabasePaths.GetDatabasePath(bankRootDirectory)` 固定返回：

```text
{bankRootDirectory}/cms-v2.db
```

## 2.1 文件资产边界

V2 内容块文件资产使用独立目录：

```text
{bankRootDirectory}
  cms-v2.db
  content-blocks/
    source/
      {ContentBlockId}/
        v{VersionNumber}.docx
    html/
      {ContentBlockId}/
        v{VersionNumber}.html
    text/
      {ContentBlockId}/
        v{VersionNumber}.txt
  handouts/
    generated/
      {HandoutVersionId}/
        {yyyyMMddHHmmssfff}-{OutputFormId}-{SafeTitle}.docx
```

路径规则：

```text
DOCX 路径由 ICmsV2FileAssetPathProvider.GetContentBlockDocxPath 生成。
HTML 预览路径由 ICmsV2FileAssetPathProvider.GetContentBlockHtmlPreviewPath 生成。
TXT 纯文本文件路径由 ICmsV2FileAssetPathProvider.GetContentBlockPlainTextPath 生成。
讲义生成 DOCX 路径由 ICmsV2FileAssetPathProvider.GetGeneratedHandoutDocxPath 生成。
返回值均为绝对路径。
ContentBlockId 和 VersionNumber 必须大于 0。
HandoutVersionId 和 OutputFormId 必须大于 0。
讲义生成文件名中的 OutputFormTitle 必须清理非法文件名字符，空标题回退为 handout。
```

旧目录边界：

```text
不使用旧 source/ 根目录保存 V2 内容块。
不使用旧 html/ 根目录保存 V2 预览。
不读取 question-bank.db。
不迁移旧题目文件。
```

`ContentBlockVersion` 与文件资产的对应关系：

```text
ContentBlockVersion.DocxPath
  保存当前版本 DOCX 的绝对路径。

ContentBlockVersion.HtmlPreviewPath
  保存当前版本 HTML 预览的绝对路径。

ContentBlockVersion.PlainText
  保存从 DOCX 提取出来的纯文本内容，用于后续搜索和健康检查。

content-blocks/text/{ContentBlockId}/v{VersionNumber}.txt
  同步保存 PlainText 文件资产，便于后续搜索索引和文件健康检查扩展。
```

## 3. 全局建模原则

- 领域对象使用英文类名。
- 主键统一使用 `int Id`。
- SQLite 表主键为自增整数主键。
- 领域属性使用 `private set`。
- 公开构造函数负责建立最小有效状态。
- 为 EF materialization 保留私有无参构造函数。
- 核心对象默认只保存 `UpdatedTime`，不保存 `CreatedTime`。
- `GeneratedFile.GeneratedTime` 是业务事实，单独保留。
- `Difficulty` 只允许出现在 `ContentBlock`、`AtomicSection`、`Section`、`SectionVariant`。
- `ContentBlockVersion` 不保存 `Difficulty`、`BlockType`、`QuestionType`。
- `TeachingNote` 独立建模，不归入 `ContentBlock`。
- 枚举在 EF Core 中按整数列存储。
- 删除行为默认使用 `Restrict`，避免误删内容资产。
- 多态引用只保存 `TargetType + TargetId`，不强行建立跨表外键。
- 跨聚合图递归循环检测留到 Application 阶段。

### ContentBlock

职责：系统核心可复用内容资产。

表名：`ContentBlocks`

字段：

```text
Id
SectionId
Title
Summary
BlockType
Difficulty
QuestionType
Status
CurrentVersionId
UpdatedTime
```

关系与约束：

- `SectionId` 指向创建 / 默认归属的 `Sections.Id`，用于记录该 `ContentBlock` 属于哪个 Section 的内容池；这不限制它后续被其他 Section、AtomicSection 或 Handout 引用。
- `Title` 允许为空字符串；没有独立名称的 `ContentBlock` 应由类型、预览摘要或上下文兜底展示。
- `CurrentVersionId` 可指向 `ContentBlockVersions.Id`。
- `ContentBlock 1 - N ContentBlockVersion`。
- `QuestionType` 只对 `BlockType = Question` 有业务意义。
- `Difficulty` 保留在 `ContentBlock`。
- `ContentBlock` 不保存小节排序、讲义排序或输出形式。
- `TeachingNote` 不归入 `ContentBlock`，只通过 `TeachingNote.TargetType + TargetId` 挂载。
- 删除行为 `Restrict`。

#### ContentBlock 彻底删除用例

第一版默认仍采用 `Restrict` 保护内容资产。只有显式调用危险接口时，才允许执行彻底删除：

```text
POST /api/cms-v2/content-blocks/{contentBlockId}/delete-cascade
```

该接口表示永久删除 `ContentBlock` 本体，不是移除某个引用。

事务边界：

- 校验 `ContentBlock` 存在。
- 如果存在活动中的 `ContentBlockEditSession`，拒绝删除，提示用户先同步或取消会话。
- 在同一个事务中清理所有引用和版本记录。
- 任一步失败时整体回滚，不允许留下半删除状态。

引用清理范围：

- 删除引用该块的 `SectionItem`。
- 删除引用上述 `SectionItem` 的 `SectionVariantItem`。
- 删除引用该块的 `AtomicSectionItem`。
- 删除引用该块的 `HandoutVersionItem`。
- 删除该块作为 child 的 `ContentBlockRelation`。
- 删除该块作为 parent 的 `ContentBlockRelation`。

`CompositeBlock` 边界：

- `CompositeBlock` 仍然是组类型 `ContentBlock`。
- 删除 `CompositeBlock` 本体时，会删除它作为 parent 的 child relations。
- 不递归删除 child `ContentBlock` 本体。

版本与文件资产：

- 删除该块的全部 `ContentBlockVersion`。
- 删除版本记录指向的 DOCX 与 HTML 预览文件资产。
- `PlainText` 当前保存在 `ContentBlockVersion.PlainText` 字段中，随版本记录一起删除。

API 返回删除摘要，用于前端展示和测试断言：

```text
contentBlockId
removedSectionItemCount
removedSectionVariantItemCount
removedAtomicSectionItemCount
removedContentBlockRelationCount
removedHandoutVersionItemCount
removedVersionCount
deletedAssetCount
```

## 当前待补齐：SectionVariant 创建与默认选择 API

本节记录已确认的 `SectionVariant` 后端目标形态。当前如果代码仍是“先创建 `SectionVariant`，再单独添加 `SectionVariantItem`”的旧链路，应视为待收口差异。

### 1. 选择预览 API

建议新增：

```text
POST /api/cms-v2/section-variants/selection-preview
```

请求：

```ts
type SectionVariantSelectionPreviewRequest = {
  sectionId: number
  difficulty: 'Basic' | 'Medium' | 'Advanced' | 'Top'
}
```

响应候选项必须由后端按当前 `Section` 的顶层 `SectionItem` 计算：

```ts
type SectionVariantSelectionCandidateDto = {
  sectionItemId: number
  parentItemId?: number | null
  sourceSortOrder: number
  targetType: 'ContentBlock' | 'AtomicSection'
  targetId: number
  resolvedDifficulty: 'Unset' | 'Basic' | 'Medium' | 'Advanced' | 'Top'
  defaultSelected: boolean
  selectable: boolean
  unavailableReason?: string
}
```

规则：

- 只返回 `SectionItem.ParentItemId == null` 的顶层项。
- 返回顺序为 `SortOrder`，再按 `SectionItem.Id` 稳定排序。
- `ContentBlock` 与组类型 `CompositeBlock` 均按 `ContentBlock.Difficulty` 判断。
- `AtomicSection` 按 `AtomicSection.Difficulty` 判断。
- `Unset` 永不默认选中。
- 已归档 `SectionItem`、缺失目标、已归档目标或非法目标仍可返回，但 `selectable=false`、`defaultSelected=false`，并给出 `unavailableReason`。
- 预览失败时前端应停留在元数据步骤，不进入选择模式。

### 2. 原子创建 API

优先扩展现有：

```text
POST /api/cms-v2/section-variants
```

目标请求：

```ts
type CreateSectionVariantRequest = {
  sectionId: number
  title: string
  description?: string
  type: SectionVariantType
  difficulty: 'Basic' | 'Medium' | 'Advanced' | 'Top'
  selectedSectionItemIds: number[]
}
```

第一版前端不提交：

```text
Status
SortOrder
```

后端负责：

- `Status` 默认为 `Draft`。
- `SortOrder` 默认为当前 `Section` 下最大值加一。
- 在一个事务中创建 `SectionVariant` 和 `SectionVariantItem`。
- 允许 `selectedSectionItemIds` 为空。
- 拒绝重复 `selectedSectionItemIds`。
- 拒绝不属于当前 `Section` 的 `SectionItem`。
- 拒绝非顶层 `SectionItem`。
- 拒绝缺失目标、已归档目标或非法目标。
- 拒绝 `Difficulty.Unset`。
- 按源 `SectionItem.SortOrder`、`SectionItem.Id` 排序后写入 `SectionVariantItem.SortOrder = 0..n-1`。

禁止前端循环调用 `AddSectionVariantItem` 来拼出创建结果。

### 3. 标题唯一性

同一个 `Section` 下不允许出现重复的 `SectionVariant.Title`。

建议规则：

- 标题 trim 后比较。
- 同一个 `Section` 内大小写不敏感地唯一。
- 不同 `Section` 之间允许同名。
- 后续补数据库唯一索引；本阶段文档先记录目标规则。

### 4. 失败与回滚

创建失败时：

- 不创建半成品 `SectionVariant`。
- 不创建半成品 `SectionVariantItem`。
- 返回清晰 `400 ProblemDetails` 或 `404 ProblemDetails`。
- 前端保留用户填写的元数据和选择状态，允许重试。

### 5. 后续预留

第一版不实现 `AtomicSectionItem` 粒度选择。未来补齐时使用：

```text
SectionVariantItem.SelectionMode
SectionVariantAtomicItemSelection
```

该扩展仍以 `SectionVariantItem` 为锚点，不直接用 `SectionVariantId + AtomicSectionId` 表达部分选择。

- 页眉页脚。
- 样式。
- 题干编号样式。

- `TeachingTopic` 输出为标题 1。
- `Section` 输出为标题 2。
- `AtomicSection` 输出为标题 3。
- 题干段落统一绑定到模板中的“例题”编号样式。
- 保留 `OutputTemplate` 页眉页脚。
- 忽略或清理源 ContentBlock DOCX 页眉页脚。
- 跨 DOCX 合并后例题编号必须全文连续。
- 失败不写 `GeneratedFile`，并清理半成品输出。

### 6. 编号技术 Spike

- 准备 `OutputTemplate.docx` 与多个 `ContentBlock-*.docx` fixture。

- 合并后所有题干必须使用统一目标模板列表定义。

## 当前补充：Handout 创建链路后端口径

本节根据 `CMS-V2-Handout-创建链路上线开发规格-rebuildUI.md` 补齐后端开发文档。它只定义目标口径，不表示以下能力已经全部实现。

### 1. Handout 与 HandoutVersion 创建职责

`Handout` 表示一组讲义的总入口。

`HandoutVersion` 表示某一份具体讲义内容组合。

创建 `Handout` 时只创建 `Handout` 本体，不自动创建 `HandoutVersion`，也不自动进入讲义编辑器。

创建 `HandoutVersion` 时才进入 `/handouts/{handoutVersionId}` 对应的编辑器页面。

后端必须保证：

- `Handout.Title` 在未归档 Handout 中全局唯一，比较前需要 trim。
- `HandoutVersion.Title` 在同一 Handout 下未归档版本中唯一，比较前需要 trim。
- 新建 `HandoutVersion` 的 `SortOrder` 由后端计算，推荐使用当前最大值加 10。
- 归档不是物理删除。
- 已归档 `Handout` 不允许继续创建 `HandoutVersion`。
- 已归档 `HandoutVersion` 不允许继续写入 item 或生成新输出，但历史 `GeneratedFile` 仍可查看和下载。

### 2. Handout 管理 API 目标

现有 `GET /api/cms-v2/handouts`、`GET /api/cms-v2/handouts/{id}`、`POST /api/cms-v2/handouts`、`GET /api/cms-v2/handouts/{id}/versions`、`POST /api/cms-v2/handouts/{id}/versions` 是基础能力。

为支撑 `/handouts` 管理页，后续还需要补齐：

```http
PATCH /api/cms-v2/handouts/{id}
PATCH /api/cms-v2/handout-versions/{id}
GET   /api/cms-v2/handouts/tree
```

其中：

- `PATCH /handouts/{id}` 用于更新标题、说明和状态。
- `PATCH /handout-versions/{id}` 用于更新标题、说明、状态和排序。
- `GET /handouts/tree` 用于返回可直接支撑管理页 Master-Detail 和 Handout 总览浮层的数据。

### 3. SectionVariant 选择树 API 目标

Handout 初始内容选择和非空讲义追加都需要按教学结构批量选择 `SectionVariant`。

推荐新增独立接口：

```http
GET /api/cms-v2/section-variants/tree
```

返回结构按以下语义组织：

```text
TeachingTopic
  Section
    SectionVariant
```

其中 `TeachingTopic` 与 `Section` 只作为分组节点，只有 `SectionVariant` 是可选叶子节点。

这个接口不同于 `GET /api/cms-v2/teaching-structure`：教学结构树服务 SectionPage 的全局定位，`section-variants/tree` 服务 Handout 的批量选择。

### 4. 批量加入 SectionVariant API 目标

Handout 创建链路中，`SectionVariantSelectionDialog` 一次可以选择多个 `SectionVariant`。

后端应提供专用批量写入接口，不要求前端循环调用单项 item API：

```http
POST /api/cms-v2/handout-versions/{id}/items/batch-add-section-variants
```

请求语义：

```json
{
  "sectionVariantIds": [1, 2, 3],
  "insertAfterItemId": null
}
```

规则：

- `sectionVariantIds` 允许为空，但空数组应直接返回空结果，不写入数据。
- 同一次请求中的重复 ID 需要去重或返回稳定业务错误，具体实现需在用例中保持一致。
- 目标 `SectionVariant` 必须存在，且不能是 `Archived`。
- 第一版允许同一个 `HandoutVersion` 中重复引用同一个 `SectionVariant`；如果产品层要求跳过已存在项，应在 API 文档中明确。
- 当 `insertAfterItemId` 为空时，追加到末尾。
- 当 `insertAfterItemId` 不为空时，必须属于当前 `HandoutVersion`。
- 写入必须在一个事务中完成，失败时不留下半成品 `HandoutVersionItem`。
- 写入后同级 `SortOrder` 必须稳定规整。

### 5. Application 用例目标

`HandoutUseCases` 后续需要明确包含以下创建链路用例：

```text
CreateHandoutAsync
UpdateHandoutAsync
CreateHandoutVersionAsync
UpdateHandoutVersionAsync
GetHandoutTreeAsync
GetSectionVariantSelectionTreeAsync
BatchAddSectionVariantsAsync
```

这些用例必须保持 server-confirmed update，不做前端乐观写入依赖。

### 6. 前端稳定编辑器保护对应的后端边界

当前 `/handouts/{handoutVersionId}` 编辑器已经可读取真实 workspace、编辑 item、输出 Word 和管理 GeneratedFile。

创建链路补齐时不应要求重写这些后端能力。

后续后端变更应优先补齐入口和批量写入能力，不改变已有 workspace、item move/remove/update、output form、generated file 的成功契约。
