# CMS V2 后端数据模型开发文档

本文档记录 CMS V2 后端数据模型的目标对象、对象职责、字段、关系、约束、数据库表结构命名和分层落点。

当前已完成范围：

- V2 后端项目骨架。
- Domain 层领域对象、枚举、领域异常和最小领域规则。
- Infrastructure 层全新 EF Core 10 + SQLite 表结构、`CmsV2DbContext`、实体配置和初始建库迁移。
- Domain 层仓储契约与 `ICmsV2UnitOfWork`。
- Infrastructure 层 EF Core 仓储实现与 `EfCmsV2UnitOfWork`。
- 标签系统 `Tag / TagBinding` 的领域模型、仓储、EF 配置、迁移、Application 用例、API 和测试。
- 教学评注新模型 `TeachingNote + TeachingNoteBinding` 的领域模型、仓储、EF 配置和迁移。
- 教学评注 Application 用例与 API 闭环。
- Application 层用例、命令 DTO、应用异常和跨实体规则。
- V2 文件资产路径策略、内容块 DOCX 文件存储、HTML 预览生成和 PlainText 提取。
- Application 层内容块文档用例。
- 讲义 DOCX 生成链路、模板套用、内容块递归展开、`GeneratedFile` 写入和版本清单记录。
- V2 本地 HTTP API、依赖注入组合根、启动迁移、异常处理和最小可用端点。

当前未完成范围：

- PDF / WordAndPdf 输出。
- 变量替换与学生版 / 教师版条件过滤。
- 完整前端页面体系中的全局标签管理页、全局 TeachingNote 管理 / 搜索页、跨页面统计入口和复杂多对象绑定选择器。
- 旧数据迁移。

## 2. 数据库边界

V2 使用独立 SQLite 数据库：

```text
cms-v2.db
```

明确不做：

```text
不读取 question-bank.db
不修改 question-bank.db
不迁移旧业务数据
不建立旧 CMS 表结构兼容层
不实现旧数据导入工具
```

`CmsV2DatabasePaths.GetDatabasePath(bankRootDirectory)` 固定返回：

```text
{bankRootDirectory}/cms-v2.db
```

## 2.1 文件资产边界

V2 内容块文件资产使用独立目录：

```text
{bankRootDirectory}
  cms-v2.db
  content-blocks/
    source/
      {ContentBlockId}/
        v{VersionNumber}.docx
    html/
      {ContentBlockId}/
        v{VersionNumber}.html
    text/
      {ContentBlockId}/
        v{VersionNumber}.txt
  handouts/
    generated/
      {HandoutVersionId}/
        {yyyyMMddHHmmssfff}-{OutputFormId}-{SafeTitle}.docx
```

路径规则：

```text
DOCX 路径由 ICmsV2FileAssetPathProvider.GetContentBlockDocxPath 生成。
HTML 预览路径由 ICmsV2FileAssetPathProvider.GetContentBlockHtmlPreviewPath 生成。
TXT 纯文本文件路径由 ICmsV2FileAssetPathProvider.GetContentBlockPlainTextPath 生成。
讲义生成 DOCX 路径由 ICmsV2FileAssetPathProvider.GetGeneratedHandoutDocxPath 生成。
返回值均为绝对路径。
ContentBlockId 和 VersionNumber 必须大于 0。
HandoutVersionId 和 OutputFormId 必须大于 0。
讲义生成文件名中的 OutputFormTitle 必须清理非法文件名字符，空标题回退为 handout。
```

旧目录边界：

```text
不使用旧 source/ 根目录保存 V2 内容块。
不使用旧 html/ 根目录保存 V2 预览。
不读取 question-bank.db。
不迁移旧题目文件。
```

`ContentBlockVersion` 与文件资产的对应关系：

```text
ContentBlockVersion.DocxPath
  保存当前版本 DOCX 的绝对路径。

ContentBlockVersion.HtmlPreviewPath
  保存当前版本 HTML 预览的绝对路径。

ContentBlockVersion.PlainText
  保存从 DOCX 提取出来的纯文本内容，用于后续搜索和健康检查。

content-blocks/text/{ContentBlockId}/v{VersionNumber}.txt
  同步保存 PlainText 文件资产，便于后续搜索索引和文件健康检查扩展。
```

## 3. 全局建模原则

- 领域对象使用英文类名。
- 主键统一使用 `int Id`。
- SQLite 表主键为自增整数主键。
- 领域属性使用 `private set`。
- 公开构造函数负责建立最小有效状态。
- 为 EF materialization 保留私有无参构造函数。
- 核心编排对象默认只保存 `UpdatedTime`，不保存 `CreatedTime`。
- `GeneratedFile.GeneratedTime` 是业务事实，单独保留。
- `Tag / TagBinding / TeachingNote / TeachingNoteBinding` 需要保存创建时间，以支持标签和评注按时间展示、追踪与审计。
- `Difficulty` 只允许出现在 `ContentBlock`、`AtomicSection`、`Section`、`SectionVariant`。
- `ContentBlockVersion` 不保存 `Difficulty`、`BlockType`、`QuestionType`。
- `TeachingNote` 独立建模，不归入 `ContentBlock`。
- 枚举在 EF Core 中按整数列存储。
- 删除行为默认使用 `Restrict`，避免误删内容资产。
- 多态引用只保存 `TargetType + TargetId`，不强行建立跨表外键。
- 跨聚合图递归循环检测留到 Application 阶段。

### ContentBlock

职责：系统核心可复用内容资产。

表名：`ContentBlocks`

字段：

```text
Id
SectionId
Title
Summary
BlockType
Difficulty
QuestionType
Status

UpdatedTime
```

关系与约束：

- `SectionId` 指向创建 / 默认归属的 `Sections.Id`，用于记录该 `ContentBlock` 属于哪个 Section 的内容池；这不限制它后续被其他 Section、AtomicSection 或 Handout 引用。
- `Title` 允许为空字符串；没有独立名称的 `ContentBlock` 应由类型、预览摘要或上下文兜底展示。
- `CurrentVersionId` 可指向 `ContentBlockVersions.Id`。

- `Difficulty` 保留在 `ContentBlock`。
- `ContentBlock` 不保存小节排序、讲义排序或输出形式。
- `TeachingNote` 不归入 `ContentBlock`，只通过 `TeachingNoteBinding` 关联到目标对象。
- 删除行为 `Restrict`。

#### ContentBlock 彻底删除用例

第一版默认仍采用 `Restrict` 保护内容资产。只有显式调用危险接口时，才允许执行彻底删除：

```text
POST /api/cms-v2/content-blocks/{contentBlockId}/delete-cascade
```

该接口表示永久删除 `ContentBlock` 本体，不是移除某个引用。

事务边界：

- 校验 `ContentBlock` 存在。
- 如果存在活动中的 `ContentBlockEditSession`，拒绝删除，提示用户先同步或取消会话。
- 在同一个事务中清理所有引用和版本记录。
- 任一步失败时整体回滚，不允许留下半删除状态。

引用清理范围：

- 删除引用该块的 `SectionItem`。
- 删除引用上述 `SectionItem` 的 `SectionVariantItem`。
- 删除引用该块的 `AtomicSectionItem`。
- 删除引用该块的 `HandoutVersionItem`。
- 删除该块作为 child 的 `ContentBlockRelation`。
- 删除该块作为 parent 的 `ContentBlockRelation`。

`CompositeBlock` 边界：

- `CompositeBlock` 仍然是组类型 `ContentBlock`。
- 删除 `CompositeBlock` 本体时，会删除它作为 parent 的 child relations。
- 不递归删除 child `ContentBlock` 本体。

版本与文件资产：

- 删除该块的全部 `ContentBlockVersion`。
- 删除版本记录指向的 DOCX 与 HTML 预览文件资产。
- `PlainText` 当前保存在 `ContentBlockVersion.PlainText` 字段中，随版本记录一起删除。

API 返回删除摘要，用于前端展示和测试断言：

```text
contentBlockId
removedSectionItemCount
removedSectionVariantItemCount
removedAtomicSectionItemCount
removedContentBlockRelationCount
removedHandoutVersionItemCount
removedVersionCount
deletedAssetCount
```

### GeneratedFile

职责：记录某一次实际生成出来的文件。

表名：`GeneratedFiles`

字段：

```text

OutputFormId
```

关系与约束：

- `OutputFormId` 指向 `OutputForms.Id`。

### Tag

职责：保存自由标签本体，用于检索、筛选和选题。

表名：`Tags`

字段：

```text
Id
Name
NormalizedName
Color
Status
CreatedTime
UpdatedTime
```

关系与约束：

- `Name` 非空。
- `NormalizedName = Name.Trim()`。
- 英文比较大小写不敏感，中文按原文，中间空格保留。
- `NormalizedName` 全局唯一。
- `Color` 保存固定 theme token，不保存随意 hex。
- 第一版颜色 token 使用 `tag-gray / tag-orange / tag-yellow / tag-green / tag-blue / tag-purple / tag-pink / tag-red` 或等价 token。
- `Status` 只允许 `Active / Archived`。
- 删除标签采用归档，不物理删除 `Tag`。

第一版不包含：

```text
TagKind
ParentId
Description
SortOrder
```

```text

TargetId
```

- `TagId` 指向 `Tags.Id`。

- Archived 标签不允许新绑定；已有绑定继续有效并可用于弱化显示。

- `NoteType` 合法。
- `EffectLevel` 可空；有值时必须合法。
- `OccurredAt` 可空，表示评注对应事件实际发生时间。
- `TeachingNote` 独立于 `ContentBlockVersion`。
- `TeachingNote` 本表不保存 `TargetType / TargetId`，绑定关系由 `TeachingNoteBinding` 表表达。

第一版不包含：

```text

Status
NextAction
SortOrder
TargetType
TargetId
```

### TeachingNoteBinding

职责：保存教学评注与目标对象之间的多对多绑定。

表名：`TeachingNoteBindings`

字段：

```text

TeachingNoteId
TargetType
TargetId
CreatedTime
```

关系与约束：

- `TeachingNoteId` 指向 `TeachingNotes.Id`。
- 第一版 `TargetType` 允许 `ContentBlock`、`Section`、`AtomicSection`、`AtomicSectionPanel`、`AtomicSectionItem`、`SectionItem`。
- `TargetId > 0`。
- `TeachingNoteBindings(TeachingNoteId, TargetType, TargetId)` 唯一。
- 一条评注可以绑定多个对象，一个对象也可以有多条评注。
- 删除 `TeachingNote` 时同时删除其 `TeachingNoteBinding`。
- 当前数据库删除行为保持全局 `Restrict`；EF 仓储删除 `TeachingNote` 时先删除对应 Binding，再删除 Note。

## 当前待补齐：SectionVariant 创建与默认选择 API

本节记录已确认的 `SectionVariant` 后端目标形态。当前如果代码仍是“先创建 `SectionVariant`，再单独添加 `SectionVariantItem`”的旧链路，应视为待收口差异。

### 1. 选择预览 API

建议新增：

```text
POST /api/cms-v2/section-variants/selection-preview
```

请求：

```ts
type SectionVariantSelectionPreviewRequest = {
  sectionId: number
  difficulty: 'Basic' | 'Medium' | 'Advanced' | 'Top'
}
```

响应候选项必须由后端按当前 `Section` 的顶层 `SectionItem` 计算：

```ts
type SectionVariantSelectionCandidateDto = {
  sectionItemId: number
  parentItemId?: number | null
  sourceSortOrder: number
  targetType: 'ContentBlock' | 'AtomicSection'
  targetId: number
  resolvedDifficulty: 'Unset' | 'Basic' | 'Medium' | 'Advanced' | 'Top'
  defaultSelected: boolean
  selectable: boolean
  unavailableReason?: string
}
```

规则：

- 只返回 `SectionItem.ParentItemId == null` 的顶层项。
- 返回顺序为 `SortOrder`，再按 `SectionItem.Id` 稳定排序。
- `ContentBlock` 与组类型 `CompositeBlock` 均按 `ContentBlock.Difficulty` 判断。
- `AtomicSection` 按 `AtomicSection.Difficulty` 判断。
- `Unset` 永不默认选中。
- 已归档 `SectionItem`、缺失目标、已归档目标或非法目标仍可返回，但 `selectable=false`、`defaultSelected=false`，并给出 `unavailableReason`。
- 预览失败时前端应停留在元数据步骤，不进入选择模式。

### 2. 原子创建 API

优先扩展现有：

```text
POST /api/cms-v2/section-variants
```

目标请求：

```ts
type CreateSectionVariantRequest = {
  sectionId: number
  title: string
  description?: string
  type: SectionVariantType
  difficulty: 'Basic' | 'Medium' | 'Advanced' | 'Top'
  selectedSectionItemIds: number[]
}
```

第一版前端不提交：

```text
Status
SortOrder
```

后端负责：

- `Status` 默认为 `Draft`。
- `SortOrder` 默认为当前 `Section` 下最大值加一。
- 在一个事务中创建 `SectionVariant` 和 `SectionVariantItem`。
- 允许 `selectedSectionItemIds` 为空。
- 拒绝重复 `selectedSectionItemIds`。
- 拒绝不属于当前 `Section` 的 `SectionItem`。
- 拒绝非顶层 `SectionItem`。
- 拒绝缺失目标、已归档目标或非法目标。
- 拒绝 `Difficulty.Unset`。
- 按源 `SectionItem.SortOrder`、`SectionItem.Id` 排序后写入 `SectionVariantItem.SortOrder = 0..n-1`。

禁止前端循环调用 `AddSectionVariantItem` 来拼出创建结果。

### 3. 标题唯一性

同一个 `Section` 下不允许出现重复的 `SectionVariant.Title`。

建议规则：

- 标题 trim 后比较。
- 同一个 `Section` 内大小写不敏感地唯一。
- 不同 `Section` 之间允许同名。
- 后续补数据库唯一索引；本阶段文档先记录目标规则。

### 4. 失败与回滚

创建失败时：

- 不创建半成品 `SectionVariant`。
- 不创建半成品 `SectionVariantItem`。
- 返回清晰 `400 ProblemDetails` 或 `404 ProblemDetails`。
- 前端保留用户填写的元数据和选择状态，允许重试。

### 5. 后续预留

第一版不实现 `AtomicSectionItem` 粒度选择。未来补齐时使用：

```text
SectionVariantItem.SelectionMode
SectionVariantAtomicItemSelection
```

该扩展仍以 `SectionVariantItem` 为锚点，不直接用 `SectionVariantId + AtomicSectionId` 表达部分选择。

## 当前补充：Handout 创建链路后端口径

本节根据 `CMS-V2-Handout-创建链路上线开发规格-rebuildUI.md` 补齐后端开发文档。它只定义目标口径，不表示以下能力已经全部实现。

### 1. Handout 与 HandoutVersion 创建职责

`Handout` 表示一组讲义的总入口。

`HandoutVersion` 表示某一份具体讲义内容组合。

创建 `Handout` 时只创建 `Handout` 本体，不自动创建 `HandoutVersion`，也不自动进入讲义编辑器。

创建 `HandoutVersion` 时才进入 `/handouts/{handoutVersionId}` 对应的编辑器页面。

后端必须保证：

- `Handout.Title` 在未归档 Handout 中全局唯一，比较前需要 trim。
- `HandoutVersion.Title` 在同一 Handout 下未归档版本中唯一，比较前需要 trim。
- 新建 `HandoutVersion` 的 `SortOrder` 由后端计算，推荐使用当前最大值加 10。
- 归档不是物理删除。
- 已归档 `Handout` 不允许继续创建 `HandoutVersion`。
- 已归档 `HandoutVersion` 不允许继续写入 item 或生成新输出，但历史 `GeneratedFile` 仍可查看和下载。

其中：

- `PATCH /handouts/{id}` 用于更新标题、说明和状态。
- `PATCH /handout-versions/{id}` 用于更新标题、说明、状态和排序。

```text
UX_AtomicSectionPanels_AtomicSectionId_TeachingRole_Difficulty
FK_AtomicSectionPanels_AtomicSections_AtomicSectionId
```

规则：

- `AtomicSectionId` 必须指向已存在的 `AtomicSection`。
- `Title` 必填。
- `TeachingRole` 不能为 `Unclassified`。
- `Difficulty` 允许为 `Unset`，表示该角色的兜底 panel。
- 同一个 `AtomicSection` 内不能存在两个相同 `TeachingRole + Difficulty` 的 panel。

### 2. 扩展表：AtomicSectionItems

新增字段：

```text
AtomicSectionPanelId nullable
TeachingRole required
```

新增索引：

```text
IX_AtomicSectionItems_AtomicSectionId_AtomicSectionPanelId_SortOrder
```

语义：

- `AtomicSectionPanelId = null` 表示未归组区域。
- `TeachingRole` 表示该引用在当前 `AtomicSection` 内的教学职责。
- `SortOrder` 是 panel 或未归组区域内的局部顺序。

### 3. 不修改 ContentBlock 归属模型

不得在 `ContentBlock` 上新增以下字段：

- `AtomicSectionId`
- `AtomicSectionPanelId`
- `SectionId`
- `TeachingRole`
- `DifficultyOverride`

`ContentBlock` 只保留内容资产自身字段。教学职责、归属和编排位置全部由引用模型表达。

### 4. 领域行为目标

`AtomicSectionPanel` 需要提供：

- 创建 panel。
- 重命名 panel。
- 修改 `TeachingRole / Difficulty`。
- 调整 `SortOrder`。
- 删除 panel。

`AtomicSectionItem` 需要提供：

- 归入 panel。
- 归入未归组区域。
- 修改 `TeachingRole`。
- 在同一 panel / 未归组区域内移动。

`ContentBlock` 需要提供：

- `ChangeDifficulty`，用于更新内容资产自身难度，并触发引用层重新归组。

### 5. 应用层用例目标

后续应用层应补齐：

```text
CreateAtomicSectionPanel
UpdateAtomicSectionPanel
MoveAtomicSectionPanel
DeleteAtomicSectionPanel
ChangeAtomicSectionItemClassification
AddAtomicSectionItem with panel context
```

自动归组规则：

```text
exact TeachingRole + Difficulty panel
  -> TeachingRole + Difficulty.Unset panel
  -> unassigned area
```

### 6. API 目标

目标接口：

```text

PATCH  /api/cms-v2/atomic-sections/{atomicSectionId}/panels/{panelId}
```

已有新增 item 接口后续需要扩展请求字段：

```text
panelId
teachingRole
afterAtomicSectionItemId
```

后端负责计算 `SortOrder`，前端不得直接提交最终排序值。

### 7. 测试目标

必须覆盖：

- panel 唯一约束。
- 空标题、`TeachingRole.Unclassified` 的领域校验。
- 创建 panel 后吸收未归组匹配 item。
- panel 不从其他 panel 抢 item。
- item 修改角色 / 难度后自动归组。
- panel 内移动只影响同 panel。
- 删除 panel 只删除引用，不删除 `ContentBlock`。
- wrap-as-AS 创建默认 `Knowledge / Example / Variant / PreClassQuiz` panel，但转换生成的 item 仍保持未归组。

### 8. 课前复习测验题与 CZ 内容清理口径

当前上线前调整需要补齐“课前复习测验题”板块，并清理 CZ 题库中已经批量录入的内容资产。该清理是一次性维护任务，不改变长期领域模型。

清理范围：

- 删除 CZ 题库中的全部 `ContentBlock`、`ContentBlockVersion`、`ContentBlockVersionPart` 与 `ContentBlockRelation`。
- 删除指向这些 `ContentBlock` 的 `SectionItem`、`AtomicSectionItem`、`HandoutVersionItem`。
- 删除因上述 `SectionItem` 产生的 `SectionVariantItem` 引用。
- 删除指向这些内容资产或 occurrence 的 `TagBinding`、`TeachingNoteBinding`；没有绑定目标的孤立 `TeachingNote` 可随实现策略一并清理或在执行报告中列明保留。
- 删除对应 `content-blocks/source`、`content-blocks/html`、`content-blocks/text` 文件资产，以及与本批内容导入相关的临时导入会话文件。

保留范围：

- 保留 `TeachingTopic`、`Section`、`AtomicSection`、`AtomicSectionPanel`。
- 保留 `AtomicSection` 的标题、说明、难度、状态。
- 保留已有 panel 的标题、教学角色、难度和排序。
- 不删除 `Handout`、`HandoutVersion`、`OutputTemplate`、`OutputForm`，除非后续执行前明确确认它们只包含本批内容测试数据。

补齐规则：

- 对所有既有 `AtomicSection`，如果缺少 `PreClassQuiz` panel，则在现有 panel 末尾追加一个。
- 追加 panel 的 `Title` 继承 `AtomicSection.Title`，`Difficulty` 继承 `AtomicSection.Difficulty`。
- 追加 panel 的 `SortOrder` 应排在该 `AtomicSection` 现有 panel 之后；新建 AS 默认值建议为 `40`。
- `PreClassQuiz` panel 保持空状态，不自动创建空 `ContentBlock`。
- 空 `PreClassQuiz` panel 参与“待完善”派生标记。

导入与输出：

- `Knowledge` panel 不提供题目导入入口；后端如收到面向 `Knowledge` panel 的题目导入请求，应拒绝或返回明确错误。
- `PreClassQuiz` panel 允许题目导入；确认导入后创建 `ContentBlockType.Question`，并创建 `TeachingRole.PreClassQuiz` 的 `AtomicSectionItem`。
- Handout Word 输出与 SectionPage 直接导出 Word 暂时跳过 `TeachingRole.PreClassQuiz` 的题目，不映射为 `练习题` 样式。

## 当前补充：三题库上线配置与运行时题库上下文

本节记录 CMS V2 第一版上线时的多题库运行配置规则。该能力只解决“同一套 V2 系统在启动时绑定到哪个本地题库目录”的问题，不把题库做成业务领域模型，也不恢复 V1 的 `/api/题库实例/{题库键}` 运行方式。

### 1. 上线题库清单

第一版固定支持三个本地题库：

```text
TEST  测试题库
GZ    高中题库
CZ    初中题库
```

三个题库必须完全隔离，各自拥有独立的 `cms-v2.db`、内容块文件资产、编辑会话文件、导入临时文件和讲义生成结果。

目标目录结构为：

```text
E:\Desktop\题库中心
  TEST\cms-v2
    cms-v2.db
    content-blocks\
    handouts\
    edit-sessions\
  GZ\cms-v2
    cms-v2.db
    content-blocks\
    handouts\
    edit-sessions\
  CZ\cms-v2
    cms-v2.db
    content-blocks\
    handouts\
    edit-sessions\
```

其中：

- `TEST` 用于功能测试、导入测试、破坏性验证和上线前回归。
- `GZ` 是正式高中题库。
- `CZ` 是正式初中题库。

### 2. 启动时选择题库

第一版采用“单后端实例绑定单个当前题库”的模型。

规则：

- 后端启动时通过配置选择一个当前题库。
- 后端运行中不支持切换题库。
- 业务 API 不增加 `{bankKey}` 路由段。
- 前端不直接传递本地题库根目录。
- 所有数据库、文件资产、编辑会话、导入会话和讲义输出都使用当前题库对应的 `RootDirectory`。

推荐配置形态：

```json
{
  "CmsV2": {
    "ActiveBankKey": "TEST",
    "Banks": [
      {
        "key": "TEST",
        "displayName": "测试题库",
        "kind": "Test",
        "rootDirectory": "E:\\Desktop\\题库中心\\TEST\\cms-v2"
      },
      {
        "key": "GZ",
        "displayName": "高中题库",
        "kind": "Production",
        "rootDirectory": "E:\\Desktop\\题库中心\\GZ\\cms-v2"
      },
      {
        "key": "CZ",
        "displayName": "初中题库",
        "kind": "Production",
        "rootDirectory": "E:\\Desktop\\题库中心\\CZ\\cms-v2"
      }
    ]
  }
}
```

### 3. 配置校验规则

启动时必须校验：

- `ActiveBankKey` 不为空。
- `Banks` 至少包含一个题库配置。
- `Banks[].key` 不为空，且大小写不敏感唯一。
- `Banks[].displayName` 不为空。
- `Banks[].kind` 只能为 `Test` 或 `Production`。
- `Banks[].rootDirectory` 不为空。
- `ActiveBankKey` 必须能匹配到某个 `Banks[].key`。
- 当前题库根目录启动时自动创建。

如果配置不合法，后端应在启动阶段失败，避免错误写入未知目录。

### 4. 兼容旧配置

旧配置 `CmsV2:BankRootDirectory` 只作为过渡兼容项：

- 如果配置了新的 `ActiveBankKey + Banks`，必须优先使用新配置。
- 如果没有配置 `Banks`，但存在非空 `BankRootDirectory`，可以按旧单题库模式启动，当前题库身份使用兼容值：

```text
bankKey = LEGACY
displayName = 当前题库
kind = Test
rootDirectory = BankRootDirectory
```

正式上线配置不得依赖该兼容模式。

### 5. 当前题库上下文

后端应抽象当前题库上下文，用于替代散落读取 `CmsV2ApiOptions.BankRootDirectory` 的方式。

当前题库上下文至少包含：

```text
BankKey
DisplayName
Kind
RootDirectory
```

其中 `Kind` 第一版只用于前端显示题库身份，不实现正式库危险操作保护。

### 6. Health 返回

`GET /api/cms-v2/health` 除原有状态外，应返回当前题库身份：

```json
{
  "status": "ok",
  "bankKey": "GZ",
  "bankDisplayName": "高中题库",
  "bankKind": "Production",
  "bankRootDirectory": "E:\\Desktop\\题库中心\\GZ\\cms-v2"
}
```

前端用该信息显示当前题库，避免用户误认当前操作环境。

### 7. 第一版明确不做

第一版不做以下能力：

- 不做运行时热切换题库。
- 不在业务 API 上增加 `{bankKey}`。
- 不恢复 V1 题库实例 API。
- 不把题库注册表写入 CMS V2 业务数据库。
- 不把题库建成 `Domain` 实体。
- 不做正式库危险操作二次确认。
- 不做跨题库复制、迁移、同步或对比。

### 8. 当前实现状态

截至 2026-06-25，三题库上线配置已按上述第一版规则落地：

- `CmsV2ApiOptions` 保留兼容字段 `BankRootDirectory`，新增 `ActiveBankKey` 与 `Banks`。
- `CmsV2BankOptions` 表达单个题库配置，字段为 `Key / DisplayName / Kind / RootDirectory`。
- `CmsV2CurrentBankResolver` 负责配置解析、字段校验、大小写不敏感 key 匹配、重复 key 检查、`Kind` 白名单检查和 `RootDirectory` 规范化。
- `CmsV2CurrentBank` 在 API 组合根中作为当前题库上下文注册，`DbContext`、数据库初始化、文件资产路径、编辑会话、导入会话和讲义生成均使用 `currentBank.RootDirectory`。
- `appsettings.json` 默认 `ActiveBankKey = TEST`，并配置 `TEST / GZ / CZ` 三个题库。
- `GET /api/cms-v2/health` 返回 `status / bankKey / bankDisplayName / bankKind / bankRootDirectory`。
- 前端 `AppShell` 只显示当前题库身份，不提供运行时切换入口。

验证口径：

- `TEST` 默认 health 应返回 `TEST / 测试题库 / Test`。
- 使用安全的临时启动或等价配置覆盖验证 `GZ / 高中题库 / Production` 与 `CZ / 初中题库 / Production`。
- 三个题库各自使用所在根目录下的独立 `cms-v2.db`。
- 业务 API 仍保持 `/api/cms-v2/...`，不增加 `{bankKey}`。

## 当前补充：SectionPage 直接导出 Word

本节记录 SectionPage 一次性导出当前 Section 为 Word 的后端规格。该能力服务于页面快速下载，不进入 Handout 生成记录体系。

### 1. API 边界

- 新增 Section 级导出接口，建议路径为 `POST /api/cms-v2/sections/{sectionId}/generate-word`。
- 接口使用当前题库上下文解析出的 `CurrentBank.RootDirectory`。
- 成功时直接返回 `.docx` 文件下载结果，文件名使用当前 Section 标题的安全文件名。
- 不新增 bankKey 路由参数。
- 不创建 Handout、HandoutVersion、OutputForm 或 GeneratedFile。
- 不写生成历史，不提供 manifest，不提供删除生成记录接口。
- 失败时沿用 CMS V2 API 现有错误响应模式。

### 2. 应用层生成规则

- 增加 Section Word 生成用例，或在现有文档生成用例中增加清晰隔离的 Section 导出入口。
- Section 导出必须复用默认 Word 模板解析逻辑，默认模板仍由 `OutputTemplatePaths` / `IOutputTemplatePathResolver` 管理。
- 生成内容元素时按当前 Section 组织：
  - Section 标题输出为 Heading 2。
  - 顶层 SectionItem 按 SortOrder / Id 排序。
  - ContentBlock 类型输出当前或锁定版本，并递归展开 ContentBlockRelation children。
  - AtomicSection 类型先输出 AtomicSection 标题为 Heading 3，再展开内部 ContentBlock。
  - AtomicSection 内部按 panel SortOrder / Id、panel 内 item SortOrder / Id、最后 unassigned 的顺序输出。
  - panel 标题不输出；panel 只用于排序分组。
- 空 AtomicSection、空 panel 不输出占位文字。
- 缺少有效 Stem 的题目沿用 Handout 生成的跳过策略，不插入 Word。
- 题目题干样式继续使用现有输出样式重绑定规则，按 AtomicSectionItem 的教学角色决定输出样式。
- `TeachingRole.PreClassQuiz` 暂时不输出，既不写入 Section Word，也不写入 Handout Word。

### 3. 文档生成器边界

- 现有 Handout Word 生成会写入讲义标题和生成时间；Section 直接导出不得写入这些内容。
- 推荐把标题 / 生成时间行为抽成生成选项，或提供独立的 Section 文档生成入口。
- 修改时必须保持现有 Handout 导出行为不变。
- Section 导出可生成临时文件再读回字节返回，临时文件不得写入 GeneratedFile 表；如落盘，应在响应完成前后做 best-effort 清理。
- 默认模板缺少必需样式时应失败，不生成不完整文件。

### 4. 测试要求

- Application 测试覆盖：Section 标题为 Heading 2、AtomicSection 标题为 Heading 3、不输出 panel 标题、不输出讲义标题和生成时间。
- Application 测试覆盖：顶层 ContentBlock、AtomicSection 内 ContentBlock、ContentBlockRelation children 的展开顺序。
- Application 测试覆盖：空 AtomicSection / 空 panel 不生成占位文本。
- Application 或 API 测试覆盖：生成 Section Word 不创建 GeneratedFile。
- API 测试覆盖：接口返回 `.docx` content type 与合理下载文件名。
- 回归测试覆盖：原 Handout Word 生成仍保留讲义标题、生成时间和 GeneratedFile 记录。

### 5. 导出容错与跳过策略

SectionPage 直接导出 Word 与 Handout Word 生成共用同一套内容解析和文档生成能力，但 SectionPage 面向“快速查看当前小节”的高频使用场景，不能因为局部内容质量问题直接阻断整份导出。后续实现应把导出问题统一分为三类：

```text
SilentSkip    静默跳过，不提示用户
WarningSkip   提示跳过，继续生成 Word
Blocking      阻断生成，不返回不完整 Word
```

静默跳过：

- 空 `AtomicSectionPanel`：不输出 panel 标题，也不输出占位文字。
- `TeachingRole.PreClassQuiz` occurrence：第一版不进入 Handout Word，也不进入 SectionPage Word。
- panel 标题：panel 只作为排序分组，不进入 Word。
- AtomicSection 内部没有任何可输出内容时，不应只留下孤立的 Heading 3。

提示跳过：

- `Question` 缺少有效 Stem。
- ContentBlock 源 docx 缺失、损坏或无法被 Aspose 打开。
- ContentBlock 没有可读取的当前版本。
- ContentBlock 版本存在但没有可输出正文。
- AtomicSection 原本存在内容，但其中所有子内容都因为可提示问题被跳过。

提示跳过的问题应进入结构化 issue 列表，包含对象类型、对象 ID、可见名称、原因、建议动作；生成阶段应从输出元素中移除对应内容，不插入 Word，也不写入 Handout 生成 manifest。SectionPage 直接下载场景不能只在文件响应 body 中丢失这些 issue，后续需要提供 Section 级预检接口，建议为：

```text
POST /api/cms-v2/sections/{sectionId}/validate-word-generation
```

该接口返回当前 Section 导出 Word 会遇到的结构化问题。`generate-word` 仍必须复用同一校验，避免预检通过但生成阶段绕过校验。

阻断生成：

- Section 不存在或不属于当前题库上下文。
- 默认输出模板不存在、无法读取或无法创建输出副本。
- 输出模板缺少本次导出必需样式，例如 `例题`、`变式`、`练习题`。
- ContentBlockRelation 出现循环或超过最大递归深度。
- `SectionItem` / `AtomicSectionItem` 引用的核心结构对象缺失，导致教学结构本身不一致。
- 锁定版本 ID 与目标 ContentBlock 不匹配。
- 运行环境无法写入临时输出文件或无法读取生成结果。

阻断问题必须返回错误响应，不下载 Word 文件，不创建 GeneratedFile，不写生成历史。

### 6. 当前实现状态

- API 已实现 `POST /api/cms-v2/sections/{sectionId}/generate-word`，使用当前题库上下文的 `CurrentBank.RootDirectory` 调用应用层生成逻辑，成功时直接返回 Word `.docx` 文件下载响应。
- API 已实现 `POST /api/cms-v2/sections/{sectionId}/validate-word-generation`，返回 `isValid / issues`，其中存在 `Blocking` issue 时 `isValid = false`；`generate-word` 复用同一校验路径，避免预检和生成判断不一致。
- 应用层入口为 `HandoutGenerationUseCases.GenerateSectionWordAsync`，返回安全文件名、Word content type、文件字节和生成 issue，不创建 Handout、HandoutVersion、OutputForm 或 GeneratedFile。
- 应用层预检入口为 `HandoutGenerationUseCases.ValidateSectionWordGenerationAsync`；`HandoutDocumentGenerationIssue` 已带 `Severity`，支持 `SilentSkip / WarningSkip / Blocking`，其中 `MissingQuestionStem`、无当前版本、源 docx 缺失或单个内容 docx 不可读按 `WarningSkip` 处理，模板不可读或缺少必需样式按 `Blocking` 处理。
- 生成阶段按 `WarningSkip` issue 移除对应 ContentBlock；因所有可输出子内容被跳过而变空的 AtomicSection Heading 3 会被清理，避免 Word 中留下孤立小节标题。
- 文档生成器已增加 `HandoutDocumentGenerationOptions`；Section 直接导出使用不输出讲义标题、生成时间和空内容占位的选项，现有 Handout Word 输出仍使用默认行为。
- Section Word 生成只使用临时文件读取字节并做 best-effort 清理，不写生成历史、manifest 或删除记录。
- 收口验证覆盖 Section Word 应用层测试、Section Word API 集成测试、CmsV2Api 回归测试、Handout Word 回归测试、前端 typecheck / build、`git diff --check` 与浏览器 smoke。

## 当前补充：新增 AS 后 SectionVariant 同步候选与批量写入

本节记录 Section 后续新增顶层 AtomicSection 时，对已有 SectionVariant 提供候选同步和批量写入的后端规格。

### 1. 应用层入口

建议在 `WordSolution.CmsV2.Application.SectionVariants` 中补充两个用例：

```csharp
public sealed record GetSectionVariantSyncCandidatesCommand(
    int SectionId,
    int SectionItemId);

public sealed record SyncSectionItemToVariantsCommand(
    int SectionId,
    int SectionItemId,
    IReadOnlyList<int> SectionVariantIds);
```

本同步用例中的 `SectionVariantIds` 不能为空。空列表表示用户没有选择任何同步目标，应由前端禁用确认按钮；后端仍必须防御性拒绝空列表，避免产生“成功但无写入”的歧义。该规则只适用于本节 `variant-sync` API，不改变 Handout 批量加入 SectionVariant 时允许空数组返回空结果的既有语义。

候选 DTO 至少包含：

```csharp
public sealed record SectionVariantSyncCandidateDto(
    int SectionVariantId,
    string Title,
    SectionVariantType Type,
    Difficulty Difficulty,
    SectionVariantStatus Status);
```

同步结果 DTO 至少包含：

```csharp
public sealed record SectionVariantSyncResultDto(
    int SectionItemId,
    IReadOnlyList<int> SyncedSectionVariantIds);
```

### 2. 候选计算规则

被同步的 `SectionItem` 必须满足：

- 存在于 `SectionId` 指定的 Section。
- `ParentItemId == null`，即 Section 顶层 item。
- `TargetType == AtomicSection`。
- 对应 `AtomicSection` 存在且未归档。

候选 `SectionVariant` 必须满足：

- `SectionVariant.SectionId == SectionId`。
- 状态为 `Draft` 或 `Active`。
- 不存在指向该 `SectionItemId` 的 `SectionVariantItem`。
- Variant 难度按现有 `IsIncludedByDifficulty(candidateDifficulty, selectedDifficulty)` 规则覆盖 AS 难度。
- `Archived` Variant 永远不进入候选。

如果 AS 难度为 `Unset`，第一版沿用现有 Variant 默认选择规则：不自动进入候选，避免误同步。

### 3. 插入顺序规则

批量同步时，后端必须按 Section 顶层顺序推导每个 Variant 的插入位置，而不是只看新 AS 的直接前后邻居。

算法规则：

1. 读取当前 Section 的顶层 `SectionItem`，按 `SortOrder, Id` 排序。
2. 找到待同步 `SectionItemId` 在顶层序列中的位置。
3. 对每个目标 Variant 读取已有 `SectionVariantItem`，并映射到它们引用的 `SectionItemId`。
4. 从待同步项向前扫描，找到最近一个已在该 Variant 中选中的前序顶层 `SectionItem`。
5. 从待同步项向后扫描，找到最近一个已在该 Variant 中选中的后序顶层 `SectionItem`。
6. 如果同时找到前序和后序，则把新 `SectionVariantItem` 插入二者之间。
7. 如果只找到前序，则插入前序之后。
8. 如果只找到后序，则插入后序之前。
9. 如果两者都不存在，则插入为该 Variant 的第一项。

`SortOrder` 分配应复用现有排序策略；当相邻排序值没有可用间隙时，可以在同一事务内重排该 Variant 的 `SectionVariantItem.SortOrder`，保持顺序稳定。

### 4. 事务与错误处理

- 批量同步必须在一个事务中完成。
- `POST` 同步时必须重新校验全部候选规则，不得信任此前 `GET` 候选查询返回的旧结果。
- 任意目标 Variant 不合法、已归档、跨 Section、已包含该 SectionItem 或不满足难度规则时，整个同步失败并回滚。
- 不允许部分 Variant 成功、部分 Variant 失败。
- 同步失败返回应用层异常，由 API 转换为现有 CMS V2 错误响应。
- 同步成功只创建 `SectionVariantItem`，不修改 `SectionItem`、`AtomicSection` 或内容资产。

### 5. API 边界

建议新增两个 Section 级 API：

```text
GET  /api/cms-v2/sections/{sectionId}/variant-sync-candidates?sectionItemId={sectionItemId}
POST /api/cms-v2/sections/{sectionId}/variant-sync
```

批量同步请求体：

```json
{
  "sectionItemId": 123,
  "sectionVariantIds": [10, 11, 12]
}
```

批量同步响应：

```json
{
  "sectionItemId": 123,
  "syncedSectionVariantIds": [10, 11, 12]
}
```

API 路径不新增 `{bankKey}`；仍使用当前后端实例绑定的题库上下文。

### 6. 测试要求

应用层测试至少覆盖：

- 新增顶层 AS 可找到同 Section 内 `Draft / Active` 且难度覆盖的候选 Variant。
- `Archived` Variant、已包含该 SectionItem 的 Variant、难度不覆盖的 Variant 不进入候选。
- 扫描式插入顺序：直接前一个 SectionItem 未在 Variant 中时，继续向前找到最近已选前序项。
- 同时存在前序和后序时插入二者之间。
- 空 `SectionVariantIds` 请求被拒绝。
- 任意目标 Variant 不合法时批量同步整体回滚。

API 集成测试至少覆盖：

- 候选查询返回结构化候选列表。
- 批量同步成功后创建对应 `SectionVariantItem`。
- 已包含或跨 Section 的请求返回错误，且不产生部分写入。
- 候选查询后 Variant 状态或内容发生变化时，批量同步阶段按最新状态重新校验并拒绝非法请求。
