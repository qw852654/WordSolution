# CMS V2 领域模型结构说明

本文档用于说明 CMS V2 后端领域模型的结构、层级关系、依赖关系、实体职责、字段含义和主要约束。  
本文档以当前 `src-v2/WordSolution.CmsV2.Domain` 中已经实现的领域模型为准。

## 1. 总体定位

CMS V2 的核心目标是围绕讲义生产组织内容：

```text
TeachingTopic 教学主题
  -> Section 小节
    -> SectionItem 小节项
      -> ContentBlock 内容块
      -> AtomicSection 原子小节
        -> AtomicSectionItem 原子小节项
          -> ContentBlock 内容块

Section 小节
  -> SectionVariant 小节变体
    -> SectionVariantItem 小节变体项
      -> SectionItem 小节项

Handout 讲义
  -> HandoutVersion 讲义版本
    -> HandoutVersionItem 讲义版本项
      -> SectionVariant 小节变体
      -> ContentBlock 内容块

OutputTemplate 输出模板
  -> OutputForm 输出形式
    -> GeneratedFile 生成文件
```

内容资产的最小复用单位是 `ContentBlock`。  
教学组织单位是 `Section`。  
最终输出组织单位是 `HandoutVersion`。  
实际生成文件由 `OutputForm` 驱动，并记录到 `GeneratedFile`。

## 2. 分层依赖关系

V2 项目采用独立分层：

```text
WordSolution.CmsV2.Api
  -> WordSolution.CmsV2.Application
  -> WordSolution.CmsV2.Infrastructure

WordSolution.CmsV2.Application
  -> WordSolution.CmsV2.Domain

WordSolution.CmsV2.Infrastructure
  -> WordSolution.CmsV2.Domain

WordSolution.CmsV2.Domain
  -> 无业务项目依赖
```

各层职责：

```text
Domain
  保存实体、枚举、领域异常、领域校验、仓储契约、文件处理契约。
  不依赖 EF Core、ASP.NET Core、文件系统或 Aspose。

Application
  编排仓储和领域对象。
  负责跨实体校验，例如版本归属、目标存在性、递归循环检测、讲义展开。
  只依赖 Domain。

Infrastructure
  实现 EF Core SQLite 持久化。
  实现仓储、Unit of Work、文件路径、DOCX 处理、讲义 Word 拼接。
  依赖 Domain。

Api
  作为本地 HTTP 入口和依赖注入组合根。
  注册 Application 用例和 Infrastructure 实现。
```

## 3. 数据库和表命名

V2 使用独立 SQLite 数据库：

```text
{BankRootDirectory}/cms-v2.db
```

初始业务表共 17 张。标签系统与教学评注新模型补齐后，目标业务表为 20 张：

```text
TeachingTopics
Sections
SectionItems
AtomicSections
AtomicSectionItems
SectionVariants
SectionVariantItems
ContentBlocks
ContentBlockVersions
ContentBlockRelations
Handouts
HandoutVersions
HandoutVersionItems
OutputTemplates
OutputForms
GeneratedFiles
Tags
TagBindings
TeachingNotes
TeachingNoteBindings
```

全局表结构原则：

- 主键统一为 `int Id`，SQLite 自增。
- 枚举按 `int` 存储。
- 核心编排对象默认只有 `UpdatedTime`，不保存 `CreatedTime`。
- `GeneratedFile` 例外，保存业务事实时间 `GeneratedTime`。
- `Tag / TagBinding / TeachingNote / TeachingNoteBinding` 需要保存创建时间，用于标签和评注按时间展示、追踪和审计。
- 删除行为默认 `Restrict`，避免误删内容资产。
- 多态引用保存 `TargetType + TargetId`，不建立跨表外键。
- 文本字段长度由 EF 配置约束：标题 200、说明 2000、备注 1000、路径 1024。

## 4. 模型层级总览

### 4.1 教学组织层

```text
TeachingTopic
  1 -> N Section

Section
  1 -> N SectionItem
  1 -> N SectionVariant

SectionItem
  -> ContentBlock
  -> AtomicSection

AtomicSection
  1 -> N AtomicSectionItem

AtomicSectionItem
  -> ContentBlock

SectionVariant
  1 -> N SectionVariantItem

SectionVariantItem
  -> SectionItem
```

### 4.2 内容资产层

```text
ContentBlock
  1 -> N ContentBlockVersion
  1 -> N ContentBlockRelation as parent
  N -> 1 ContentBlockRelation as child

ContentBlockRelation
  ParentBlockId -> ContentBlock
  ChildBlockId -> ContentBlock
  LockedContentBlockVersionId -> ContentBlockVersion?
```

### 4.3 讲义输出层

```text
Handout
  1 -> N HandoutVersion

HandoutVersion
  1 -> N HandoutVersionItem
  1 -> N OutputForm

HandoutVersionItem
  -> SectionVariant
  -> ContentBlock

OutputTemplate
  1 -> N OutputForm

OutputForm
  1 -> N GeneratedFile
```

### 4.4 教学备注层

```text
TeachingNote
  1 -> N TeachingNoteBinding

TeachingNoteBinding
  -> ContentBlock
  -> Section
  -> AtomicSection
  -> AtomicSectionPanel
  -> AtomicSectionItem
  -> SectionItem
```

`TeachingNote` 是独立评注模型，不归入 `ContentBlock`，也不作为内容资产输出。`TeachingNote` 本表不保存 `TargetType / TargetId`。

### 4.5 标签层

```text
Tag
  1 -> N TagBinding

TagBinding
  -> ContentBlock
  -> AtomicSection
  -> Section
```

`Tag` 是自由标签，用于检索、筛选和选题。第一版不设计 `TagKind`、`ParentId` 或标签树。

## 5. 实体字段说明

### 5.1 TeachingTopic

表名：`TeachingTopics`  
职责：表示教学内容在知识结构中的位置。它负责“定位”，不直接承载讲义版本、内容块版本或生成记录。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 教学主题主键。 |
| `ParentId` | `int?` | 父主题 ID，用于形成教学主题树。为空表示根主题。 |
| `Name` | `string` | 主题名称，例如“机械能守恒”。必填。 |
| `Description` | `string?` | 主题说明，用于记录该主题的教学范围或备注。 |
| `SortOrder` | `int` | 同级主题排序值。必须大于等于 0。 |
| `Status` | `TeachingTopicStatus` | 主题状态，当前支持 `Active`、`Archived`。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `ParentId` 自关联 `TeachingTopics.Id`。
- 删除父主题时使用 `Restrict`。
- `ParentId` 建索引，便于读取子主题。

### 5.2 Section

表名：`Sections`  
职责：表示一个教学主题下的教学组织单元，回答“这个主题应该怎么讲”。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 小节主键。 |
| `TeachingTopicId` | `int` | 所属教学主题 ID。 |
| `Title` | `string` | 小节标题。必填。 |
| `Description` | `string?` | 小节说明，用于描述教学目标或内容范围。 |
| `Type` | `SectionType` | 小节类型，例如常规课、一轮复习、专题、考试训练。 |
| `Difficulty` | `Difficulty` | 小节整体难度。 |
| `Status` | `SectionStatus` | 小节状态，支持草稿、可用、归档。 |
| `SortOrder` | `int` | 同一主题下的小节排序值。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `TeachingTopicId` 外键指向 `TeachingTopics.Id`。
- `(TeachingTopicId, SortOrder)` 建索引。
- 删除教学主题时受 `Restrict` 保护。

### 5.3 SectionItem

表名：`SectionItems`  
职责：表示小节内部的有序引用项。它可以引用内容块，也可以引用原子小节。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 小节项主键。 |
| `SectionId` | `int` | 所属小节 ID。 |
| `TargetType` | `SectionItemTargetType` | 引用目标类型，只允许 `ContentBlock` 或 `AtomicSection`。 |
| `TargetId` | `int` | 引用目标 ID。与 `TargetType` 一起定位目标对象。 |
| `ReferenceMode` | `ReferenceMode` | 内容块引用模式：跟随最新版或锁定版本。 |
| `LockedContentBlockVersionId` | `int?` | 锁定的内容块版本 ID。仅当目标是 `ContentBlock` 且引用模式为 `LockedVersion` 时使用。 |
| `TitleOverride` | `string?` | 在当前小节中的显示标题覆盖值，不改变源对象标题。 |
| `ParentItemId` | `int?` | 父小节项 ID，用于表达小节内部层级。 |
| `SortOrder` | `int` | 同级或同小节下的排序值。 |
| `SelectionLayer` | `SelectionLayer?` | 选用层级，例如基础必讲、提高补充、课堂备用。 |
| `TeachingUseOverride` | `TeachingUse?` | 当前小节中的教学用途覆盖，例如讲解、练习、作业、复习。 |
| `Status` | `SectionStatus` | 小节项状态。 |
| `Note` | `string?` | 小节项备注。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `SectionId` 外键指向 `Sections.Id`。
- `ParentItemId` 自关联 `SectionItems.Id`。
- `LockedContentBlockVersionId` 外键指向 `ContentBlockVersions.Id`。
- `TargetType` 数据库检查约束只允许 1 或 2。
- 当 `TargetType` 不是 `ContentBlock` 时，`ReferenceMode` 必须为 `FollowLatest`，且不能有 `LockedContentBlockVersionId`。
- 当 `ReferenceMode` 为 `LockedVersion` 时，必须提供 `LockedContentBlockVersionId`。
- `(SectionId, SortOrder)`、`(TargetType, TargetId)`、`ParentItemId`、`LockedContentBlockVersionId` 建索引。

### 5.4 AtomicSection

表名：`AtomicSections`  
职责：表示一组不可再嵌套小节的教学片段模板。它本身不直接引用其他原子小节，只通过 `AtomicSectionItem` 引用内容块。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 原子小节主键。 |
| `SectionId` | `int` | 创建 / 默认归属的 Section ID。用于记录该 AtomicSection 属于哪个 Section 的内容池。 |
| `Title` | `string` | 原子小节标题。必填。 |
| `Description` | `string?` | 原子小节说明。 |
| `Type` | `AtomicSectionType` | 原子小节类型，例如概念建立、方法讲解、例题讲解、错因分析。 |
| `Difficulty` | `Difficulty` | 原子小节难度。 |
| `Status` | `AtomicSectionStatus` | 原子小节状态。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `SectionId` 外键指向 `Sections.Id`，记录创建 / 默认归属，不限制后续引用关系。
- 被 `SectionItem` 多态引用。
- 通过 `AtomicSectionItem` 持有内容块列表。

### 5.5 AtomicSectionItem

表名：`AtomicSectionItems`  
职责：表示原子小节内部的内容块引用。它只能引用 `ContentBlock`，不能引用 `AtomicSection` 或 `Section`。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 原子小节项主键。 |
| `AtomicSectionId` | `int` | 所属原子小节 ID。 |
| `ContentBlockId` | `int` | 引用的内容块 ID。 |
| `ReferenceMode` | `ReferenceMode` | 引用内容块时采用跟随最新版或锁定版本。 |
| `LockedContentBlockVersionId` | `int?` | 锁定的内容块版本 ID。 |
| `TitleOverride` | `string?` | 在原子小节中的显示标题覆盖值。 |
| `SortOrder` | `int` | 原子小节内部排序值。 |
| `Note` | `string?` | 备注。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `AtomicSectionId` 外键指向 `AtomicSections.Id`。
- `ContentBlockId` 外键指向 `ContentBlocks.Id`。
- `LockedContentBlockVersionId` 外键指向 `ContentBlockVersions.Id`。
- `ReferenceMode = LockedVersion` 时必须提供 `LockedContentBlockVersionId`。
- `(AtomicSectionId, SortOrder)`、`ContentBlockId`、`LockedContentBlockVersionId` 建索引。

### 5.6 SectionVariant

表名：`SectionVariants`  
职责：表示同一小节下不同教学用途的变体，例如讲解版、练习版、作业版、复习版。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 小节变体主键。 |
| `SectionId` | `int` | 所属小节 ID。 |
| `Title` | `string` | 变体标题。必填。 |
| `Description` | `string?` | 变体说明。 |
| `Type` | `SectionVariantType` | 变体类型，例如讲解、练习、作业、复习、考试训练。 |
| `Difficulty` | `Difficulty` | 变体难度。 |
| `Status` | `SectionVariantStatus` | 变体状态。 |
| `SortOrder` | `int` | 同一小节下的排序值。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `SectionId` 外键指向 `Sections.Id`。
- `(SectionId, SortOrder)` 建索引。

### 5.7 SectionVariantItem

表名：`SectionVariantItems`  
职责：表示小节变体选用了哪些 `SectionItem`，以及选用顺序。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 小节变体项主键。 |
| `SectionVariantId` | `int` | 所属小节变体 ID。 |
| `SectionItemId` | `int` | 被选用的小节项 ID。 |
| `SortOrder` | `int` | 在小节变体中的排序值。 |
| `Note` | `string?` | 选用备注。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `SectionVariantId` 外键指向 `SectionVariants.Id`。
- `SectionItemId` 外键指向 `SectionItems.Id`。
- `(SectionVariantId, SectionItemId)` 唯一，避免同一变体重复选用同一小节项。
- Application 层校验 `SectionVariant` 和 `SectionItem` 必须属于同一个 `Section`。

### 5.8 ContentBlock

表名：`ContentBlocks`  
职责：表示可复用内容资产，是系统长期保存和复用的核心对象。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 内容块主键。 |
| `SectionId` | `int` | 创建 / 默认归属的 Section ID。用于记录该 ContentBlock 属于哪个 Section 的内容池。 |
| `Title` | `string` | 内容块标题。允许为空字符串；大量 ContentBlock 可以没有独立名称。 |
| `Summary` | `string?` | 内容摘要或备注。 |
| `BlockType` | `ContentBlockType` | 内容块类型，例如知识点、题目、解析、方法总结、例题组。 |
| `Difficulty` | `Difficulty` | 内容块难度。 |
| `QuestionType` | `QuestionType?` | 题型。仅当 `BlockType = Question` 时允许设置。 |
| `Status` | `ContentBlockStatus` | 内容块状态。 |
| `CurrentVersionId` | `int?` | 当前内容版本 ID。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `SectionId` 外键指向 `Sections.Id`，记录创建 / 默认归属；不限制该 ContentBlock 被其他 Section、AtomicSection 或 Handout 引用。
- `CurrentVersionId` 外键指向 `ContentBlockVersions.Id`。
- 非题目内容块不能设置有效 `QuestionType`。
- 被 `SectionItem`、`AtomicSectionItem`、`HandoutVersionItem`、`ContentBlockRelation` 引用。
- `Difficulty` 只保存在 `ContentBlock` 主对象，不保存在 `ContentBlockVersion`。

### 5.9 ContentBlockVersion

表名：`ContentBlockVersions`  
职责：表示内容块的一次具体 DOCX 版本。正文、预览和纯文本都围绕版本保存。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 内容块版本主键。 |
| `ContentBlockId` | `int` | 所属内容块 ID。 |
| `VersionNumber` | `int` | 版本号，从 1 开始递增。 |
| `DocxPath` | `string` | 当前版本 DOCX 文件绝对路径。必填。 |
| `HtmlPreviewPath` | `string?` | 当前版本 HTML 预览文件绝对路径。 |
| `PlainText` | `string?` | 从 DOCX 提取出的纯文本，用于搜索和健康检查。 |
| `IsCurrent` | `bool` | 是否为当前版本。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `ContentBlockId` 外键指向 `ContentBlocks.Id`。
- `(ContentBlockId, VersionNumber)` 唯一。
- `(ContentBlockId, IsCurrent)` 建索引，便于查找当前版本。
- 不保存 `Difficulty`、`BlockType`、`QuestionType`，这些属于 `ContentBlock` 主对象。

### 5.10 ContentBlockRelation

表名：`ContentBlockRelations`  
职责：表示组合内容块对子内容块的有序引用。它用于组合块展开和讲义生成。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 内容块关系主键。 |
| `ParentBlockId` | `int` | 父内容块 ID，也就是组合块。 |
| `ChildBlockId` | `int` | 子内容块 ID。 |
| `ReferenceMode` | `ReferenceMode` | 子块引用版本模式。 |
| `LockedContentBlockVersionId` | `int?` | 锁定的子内容块版本 ID。 |
| `TitleOverride` | `string?` | 在父块结构中的显示标题覆盖值。 |
| `SortOrder` | `int` | 子块在父块中的排序值。 |
| `Note` | `string?` | 关系备注。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `ParentBlockId` 外键指向 `ContentBlocks.Id`。
- `ChildBlockId` 外键指向 `ContentBlocks.Id`。
- `LockedContentBlockVersionId` 外键指向 `ContentBlockVersions.Id`。
- 禁止 `ParentBlockId == ChildBlockId`。
- `ReferenceMode = LockedVersion` 时必须提供 `LockedContentBlockVersionId`。
- 递归循环检测在 Application 层执行。
- `(ParentBlockId, SortOrder)`、`ChildBlockId`、`LockedContentBlockVersionId` 建索引。

### 5.11 Handout

表名：`Handouts`  
职责：表示讲义方案的顶层对象，回答“这份材料是什么”。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 讲义主键。 |
| `Title` | `string` | 讲义标题。必填。 |
| `Description` | `string?` | 讲义说明。 |
| `Status` | `HandoutStatus` | 讲义状态。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- 一个 `Handout` 可以有多个 `HandoutVersion`。
- `Handout` 本身不直接保存编排项，编排项属于 `HandoutVersion`。

### 5.12 HandoutVersion

表名：`HandoutVersions`  
职责：表示讲义的一套可编排版本。当前讲义输出和生成链路以 `HandoutVersion` 为单位展开。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 讲义版本主键。 |
| `HandoutId` | `int` | 所属讲义 ID。 |
| `Title` | `string` | 讲义版本标题。必填。 |
| `Description` | `string?` | 讲义版本说明。 |
| `Type` | `HandoutVersionType` | 讲义版本类型，例如普通、复习、专题、考试训练。 |
| `Status` | `HandoutVersionStatus` | 讲义版本状态。 |
| `SortOrder` | `int` | 同一讲义下版本排序值。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `HandoutId` 外键指向 `Handouts.Id`。
- `(HandoutId, SortOrder)` 建索引。
- 一个 `HandoutVersion` 可以有多个 `HandoutVersionItem` 和多个 `OutputForm`。

### 5.13 HandoutVersionItem

表名：`HandoutVersionItems`  
职责：表示讲义版本中的有序编排项。第一版可以直接引用小节变体、原子小节或内容块。

字段：

| 字段 | 类型 | 含义和作用 |
| --- | --- | --- |
| `Id` | `int` | 讲义版本项主键。 |
| `HandoutVersionId` | `int` | 所属讲义版本 ID。 |
| `TargetType` | `HandoutVersionItemTargetType` | 目标类型。第一版只允许 `SectionVariant`、`AtomicSection` 或 `ContentBlock`。 |
| `TargetId` | `int` | 目标对象 ID。 |
| `SortOrder` | `int` | 在讲义版本中的排序值。 |
| `TitleOverride` | `string?` | 在讲义中的显示标题覆盖值。 |
| `Note` | `string?` | 讲义项备注。 |
| `UpdatedTime` | `DateTimeOffset` | 最后更新时间。 |

关系和约束：

- `HandoutVersionId` 外键指向 `HandoutVersions.Id`。
- `TargetType + TargetId` 是多态引用。
- 数据库检查约束第一版只允许 `SectionVariant`、`AtomicSection` 和 `ContentBlock`。
- 领域构造拒绝直接引用 `Section`、`SectionItem`、`AtomicSectionItem`、`TeachingTopic` 或 `ContentBlockVersion`。
- `(HandoutVersionId, SortOrder)`、`(TargetType, TargetId)` 建索引。

## 7. 核心规则

### 7.1 版本引用规则

使用 `ReferenceMode` 的对象包括：

```text
SectionItem
AtomicSectionItem
ContentBlockRelation
```

规则：

- `FollowLatest` 表示生成或展开时使用内容块当前版本。
- `LockedVersion` 表示固定使用 `LockedContentBlockVersionId` 指向的版本。
- `LockedVersion` 必须提供 `LockedContentBlockVersionId`。
- 版本是否属于对应内容块由 Application 层检查。

### 7.2 多态引用规则

多态引用不建立数据库外键，统一使用：

```text
TargetType
TargetId
```

原因：

- 不同目标表无法用单一外键表达。
- Domain 负责约束可选目标类型。
- Application 负责检查目标是否真实存在。

当前多态引用：

```text
SectionItem.TargetType + TargetId
  -> ContentBlock
  -> AtomicSection

HandoutVersionItem.TargetType + TargetId
  -> SectionVariant
  -> AtomicSection
  -> ContentBlock

TagBinding.TargetType + TargetId
  -> ContentBlock
  -> AtomicSection
  -> Section

TeachingNoteBinding.TargetType + TargetId
  -> ContentBlock
  -> Section
  -> AtomicSection
  -> AtomicSectionPanel
  -> AtomicSectionItem
  -> SectionItem
```

### 7.3 组合块规则

`ContentBlockRelation` 表示父内容块包含子内容块。

规则：

- 父块不能直接包含自己。
- 递归循环检测在 Application 层执行。
- 讲义生成时最大展开深度为 10。
- 父块自身先输出，再按 `SortOrder, Id` 输出子块。

### 7.4 讲义生成规则

讲义 Word 生成以 `OutputForm` 为入口：

```text
OutputForm
  -> HandoutVersion
    -> HandoutVersionItem
      -> SectionVariant
        -> SectionVariantItem
          -> SectionItem
      -> AtomicSection
      -> ContentBlock
  -> OutputTemplate
  -> GeneratedFile
```

规则：

- 当前只支持 `OutputFormat.Word`。
- `Pdf` 和 `WordAndPdf` 当前抛应用异常。
- 模板 DOCX 必须存在。
- 内容块 DOCX 必须存在。
- `HandoutVersionItem.TargetType = AtomicSection` 时，直接整体展开 `AtomicSectionItem`，不创建 `SectionItem`，不反向修改源 `Section`。
- 第一版不对直接引用的 `AtomicSection` 做内部局部选择或 Difficulty 过滤。
- 生成成功后写入 `GeneratedFile`。
- 生成失败不写入 `GeneratedFile`，并尽量清理半成品文件。

## 10. 当前模型不包含的内容

当前领域模型明确不包含：

- 旧 `question-bank.db` 兼容结构。
- 旧题库数据迁移模型。
- 前端页面状态模型。
- 用户、权限、多人协作、SaaS 租户。
- 独立媒体资源库。
- PDF 生成结果细分表。
- 变量替换、条件内容、学生版 / 教师版过滤规则的完整模型。
- Word 本地深度编辑会话模型。

这些能力如后续需要，应作为新阶段补充，不应混入当前 17 个核心模型的职责中。

## 11. 后续补充能力：ContentBlockEditSession

`ContentBlockEditSession` 表示 `ContentBlock` 的 Word 编辑会话能力。

当前结论：

- 它不是当前 17 个核心持久领域模型之一。
- 第一版应作为后续补充能力实现。
- 会话可以先采用 transient store，不默认新增数据库表。
- 它服务于 `ContentBlock` 当前版本 DOCX 的本地编辑、状态查询、同步和取消。
- 同步成功后应通过现有 `ContentBlockVersion` 机制生成新版本，并更新 `ContentBlock.CurrentVersionId`。
- HTML 预览和 PlainText 仍复用现有 `IContentBlockDocumentProcessor`。

必须抽象的后端策略：

- `IContentBlockEditSessionLauncher`：负责启动编辑会话。
- 本地版本可以通过操作系统打开临时 DOCX。
- 未来云端版本可以替换为云端编辑、外部 URI 或其他启动方式。
- 前端不感知具体启动策略。

禁止：

- 不调用 V1 `编辑会话` 实现。
- 不修改 `VSTO/`。
- 不修改 `Word本地文件操作核心库/`。
- 不把本地 Word 打开方式写入前端契约。

## 12. SectionVariant 定稿语义

`SectionVariant` 表示从一个 `Section` 派生出的教学用途方案。它不是 `Section` 本体，也不复制 `Section` 的完整结构。

关系应保持为：

```text
TeachingTopic
  Section
    SectionItem
    SectionVariant
      SectionVariantItem -> SectionItemId
```

核心规则：

- `Section` 是完整知识池和完整教学结构。
- `SectionVariant` 是 `Section` 的子级方案，例如基础讲解版、提高版、一轮复习版。
- `SectionVariantItem` 只引用 `SectionItemId`。
- `SectionVariantItem` 不直接引用 `ContentBlockId`、`AtomicSectionId` 或前端 `flowItemId`。
- `SectionVariant` 不复制 `ContentBlock`、`AtomicSection`、`CompositeBlock`、DOCX 或 HTML 预览。

`SectionItem.TargetType` 第一版仍只允许：

```text
ContentBlock
AtomicSection
```

`CompositeBlock` 不是持久领域模型，也不是 `SectionItem.TargetType`。当 `ContentBlock.BlockType` 为 `ExampleGroup`、`ExerciseGroup`、`VariantGroup` 等组类型时，前端可以使用 `CompositeBlock` 组件渲染它。

### 12.1 难度字段归属

统一 `Difficulty` 枚举只允许出现在：

```text
Section
SectionVariant
AtomicSection
ContentBlock
```

不应出现在：

```text
SectionItem
AtomicSectionItem
ContentBlockVersion
HandoutVersion
SectionVariantItem
```

当前 `AtomicSection` 已经具备 `Difficulty` 字段；后续任务不应再把它列为缺口。

### 12.2 SectionVariant 默认选择输入

后端默认选择只读取顶层 `SectionItem` 的目标对象难度。

顶层 `SectionItem` 定义为：

```text
SectionItem.ParentItemId == null
```

目标难度来源：

```text
ContentBlock SectionItem      -> ContentBlock.Difficulty
CompositeBlock 展示项          -> ContentBlock.Difficulty
AtomicSection SectionItem     -> AtomicSection.Difficulty
```

不得使用以下字段决定默认勾选：

```text
SectionVariant.Type
SectionItem.SelectionLayer
SectionItem.TeachingUseOverride
ContentBlock.BlockType
AtomicSection.Type
Section.Difficulty
```

难度包含规则：

```text
Basic    -> Basic
Medium   -> Basic + Medium
Advanced -> Basic + Medium + Advanced
Top      -> Basic + Medium + Advanced + Top
Unset    -> 永不默认选中
```

### 12.3 未来 AtomicSection 部分选择模型

第一版 `SectionVariantItem` 只选择整个顶层 `SectionItem`。

未来如需支持“同一个 `AtomicSection` 下部分选择”，必须以 `SectionVariantItem` 为锚点扩展：

```text
SectionVariantItem
  SelectionMode: Whole | Partial

SectionVariantAtomicItemSelection
  SectionVariantItemId
  AtomicSectionItemId
  SortOrder
  Note
  UpdatedTime
```

不要使用 `SectionVariantId + AtomicSectionId` 直接表达部分选择，因为同一个 `AtomicSection` 未来可能通过不同 `SectionItem` 多次出现在同一个 `Section` 中。
## 当前定稿：AtomicSectionPanel 领域模型补充

本节用于补齐 `AtomicSection` 板块化题目演化工作流的目标领域模型。若本文前文仍以 “17 张表” 或 “只有 Section / AtomicSection / ContentBlock / Handout 四处 Difficulty” 描述当前模型，应按本节作为后续开发口径。当前数据库均为模拟数据，可以废弃重建，因此不考虑旧数据迁移。

### 1. AtomicSection 的职责

`AtomicSection` 表示一个讲解最小单元。它不是题组，也不是单个题目；它用于组织一个教学片段中的知识点、例题、变式题、练习题、课后练习、课前复习测验题等内容。

新建 `AtomicSection` 时自动创建 `Knowledge / Example / Variant / PreClassQuiz` 四个默认 `AtomicSectionPanel`。这些默认 panel 继承所属 `AtomicSection` 的 `Title` 和 `Difficulty`，`SortOrder` 分别为 `10 / 20 / 30 / 40`。其中 `Knowledge` panel 默认创建一个同名、同难度的 `KnowledgePoint ContentBlock`，并创建对应 `AtomicSectionItem`；`Example / Variant / PreClassQuiz` panel 默认保持空状态，尤其 `PreClassQuiz` 不自动创建任何 `ContentBlock`。

`AtomicSection.Status` 支持 `Draft / Active / Archived`，并可通过应用层用例和本地 API 显式更新。

### 2. AtomicSectionPanel

新增领域实体 `AtomicSectionPanel`，用于表达 `AtomicSection` 内部的教学板块。

字段：

- `Id`
- `AtomicSectionId`
- `Title`
- `TeachingRole`
- `Difficulty`
- `SortOrder`
- `UpdatedTime`

第一版不包含：

- `Description`
- `Status`
- `Note`
- `DocxPath`
- `CurrentVersionId`

约束：

- `AtomicSectionId > 0`
- `Title` 必填，默认使用所属 `AtomicSection.Title`，后续允许用户重命名。
- `TeachingRole != Unclassified`
- `Difficulty` 使用全局 `Difficulty` 枚举，允许 `Unset`。
- `SortOrder >= 0`
- 同一个 `AtomicSection` 内 `(TeachingRole, Difficulty)` 唯一。

### 3. AtomicSectionTeachingRole

新增枚举 `AtomicSectionTeachingRole`：

```text
Unclassified = 0
Knowledge    = 1
Example      = 2
Variant      = 3
Practice     = 4
Homework     = 5
PreClassQuiz = 6
```

`TeachingRole` 表示内容在 `AtomicSection` 内部承担的教学职责，不等同于传统题型 `QuestionType`。

`PreClassQuiz` 表示“课前复习测验题”，用于在下堂课之前进行测验练习。它是 `AtomicSectionTeachingRole`，不是新的 `ContentBlockType` 或 `QuestionType`。

### 4. AtomicSectionItem

`AtomicSectionItem` 继续表示 `AtomicSection` 内对内容的引用。它需要补充：

- `AtomicSectionPanelId?`
- `TeachingRole`

语义：

- `AtomicSectionPanelId == null` 表示未归组区域。
- `TeachingRole` 表示该引用在当前 `AtomicSection` 中的教学职责。
- `SortOrder` 表示在所属 panel 或未归组区域中的局部顺序。

`AtomicSectionItem` 不复制 `ContentBlock`，不拥有 `.docx`，不拥有 `ContentBlockVersion`。

### 5. ContentBlock 边界

`ContentBlock` 仍然是长期内容资产。它不记录：

- 所属 `AtomicSection`
- 所属 `AtomicSectionPanel`
- 所属 `Section`
- 所属 `Handout`
- `TeachingRole`
- `DifficultyOverride`

如果需要修改内容资产难度，使用 `ContentBlock.ChangeDifficulty`。归属和教学用途由引用层表达。

### 6. 自动归组规则

当系统需要把一个 `AtomicSectionItem` 放入 panel 时，使用以下顺序：

1. 精确匹配：`TeachingRole + Difficulty`
2. 兜底匹配：`TeachingRole + Difficulty.Unset`
3. 无匹配：放入未归组区域

触发场景：

- 在 panel 中新建内容。
- 在未归组区新建内容。
- 修改 `AtomicSectionItem.TeachingRole`。
- 修改被引用 `ContentBlock.Difficulty`。
- 新建 panel。
- 修改 panel 的 `TeachingRole / Difficulty`。
- 多个块升级为 `AtomicSection`。

新建 panel 时，只吸收当前未归组区域中匹配的 item，不从其他 panel 或兜底 panel 中抢内容。

### 7. 创建默认值

在 panel 中新建内容时：

- `Knowledge` -> `ContentBlockType.KnowledgePoint` + `TeachingRole.Knowledge`
- `Example` -> `ContentBlockType.Question` + `TeachingRole.Example`
- `Variant` -> `ContentBlockType.Question` + `TeachingRole.Variant`
- `Practice` -> `ContentBlockType.Question` + `TeachingRole.Practice`
- `Homework` -> `ContentBlockType.Question` + `TeachingRole.Homework`
- `PreClassQuiz` -> `ContentBlockType.Question` + `TeachingRole.PreClassQuiz`

内容难度默认使用 panel 的 `Difficulty`。如果 panel 难度为 `Unset`，新内容难度也为 `Unset`。

`Knowledge` panel 第一版不提供“导入题目”入口，因为该 panel 用于知识点内容。`PreClassQuiz` panel 允许导入题目；导入后的内容仍然是普通 `ContentBlockType.Question`，只是在当前 `AtomicSectionItem` occurrence 上记录 `TeachingRole.PreClassQuiz`。

当前输出边界：`PreClassQuiz` panel 与其中的 `AtomicSectionItem` 暂不进入 Handout Word 输出，也不进入 SectionPage 直接导出 Word。生成 render plan 时遇到该角色应跳过，不映射为 `练习题` 样式。

在 `AtomicSection` 顶层未归组区域新建内容时，默认：

- `ContentBlockType.Question`
- `TeachingRole.Unclassified`
- `Difficulty.Unset`
- `AtomicSectionPanelId = null`

### 8. 排序和删除

排序：

- panel 按 `SortOrder, Id` 排序。
- panel 内 item 按 `SortOrder, Id` 排序。
- 未归组 item 按 `SortOrder, Id` 排序。
- 上移 / 下移只在同一个 panel 或未归组区域内发生。
- 跨 panel 移动通过修改角色或难度触发自动归组。

删除 panel：

- 删除 panel 本体。
- 删除该 panel 下的 `AtomicSectionItem` 引用。
- 不删除 `ContentBlock` 本体。
- 不删除 `ContentBlockVersion`。
- 不删除 `.docx / html / plaintext` 文件资产。

### 9. Wrap As AtomicSection

多个顶层块升级为 `AtomicSection` 时：

- 创建 `AtomicSection` 本体。
- 同时创建默认 `Knowledge / Example / Variant / PreClassQuiz` 四个空 panel。
- 原选中块转为 `AtomicSectionItem`。
- 新 item 的 `AtomicSectionPanelId = null`。
- `ContentBlockType.KnowledgePoint` 默认映射为 `TeachingRole.Knowledge`。
- `ContentBlockType.Question` 默认映射为 `TeachingRole.Unclassified`。
- 其他类型默认映射为 `TeachingRole.Unclassified`。
- 既有转换 item 不自动归入默认 panel。

## 当前补充：ContentBlockVersionPart 与题目结构

题目结构化预览、输出样式重绑定和多题导入的完整领域约定见：

```text
docs/cms-v2/backend/题目结构化预览-输出样式重绑定-多题导入开发文档.md
```

领域层目标：

- 新增 `ContentBlockPartType`，表达 `Stem / Answer / Analysis / Hint / Other`。
- 新增 `ContentBlockPartParseStatus`，表达版本结构解析状态。
- 新增 `ContentBlockVersionPart`，挂在 `ContentBlockVersion` 下。
- `ContentBlockVersionPart` 不保存 HTML，只保存 Part 元数据、纯文本、样式来源和警告。
- `ContentBlockVersion` 需要记录 `PartParseStatus` 与 `PartParseMessage`。
- Word 样式只表达内容结构，不表达教学身份。
- `TeachingRole` 仍由 `AtomicSectionItem` / `AtomicSectionPanel` / 输出 occurrence 决定，不从 Word 样式推断。
- 多题导入使用临时 Word 会话：系统创建并自动打开临时 Word，用户保存关闭后自动切割；不得把主流程建模为上传 `.docx` 文件。
- 多题导入临时记录不进入正式业务表；第一版使用文件系统临时会话，目录建议为 `edit-sessions/question-imports/{sessionId}`。

当前状态校准：

- `ContentBlockPartType`、`ContentBlockPartParseStatus`、`ContentBlockVersionPart` 已经有基础实现，后续不新增第二套领域模型。
- 严格语义已经校准：结构化解析阶段缺少 Stem 失败、Part 输出固定顺序、非 `Question` 默认 `NotApplicable`、`Other` 不作为输出重绑定兜底、warning 必须进入前端可见链路；讲义 Word 输出阶段缺 Stem 的题目块返回 `MissingQuestionStem` 可跳过问题，生成时跳过该块，不插入 Word，也不写入 manifest sources。
- 临时多题导入会话不进入正式领域实体表；当前使用文件系统临时会话和批量确认用例。上传式 session 是历史偏差，已替换。
## 当前补充：题库上下文不是领域模型

CMS V2 第一版上线需要支持 `TEST / GZ / CZ` 三个本地题库，但该能力属于运行时配置与基础设施边界，不属于领域模型。

### 1. 三题库定位

```text
TEST  测试题库
GZ    高中题库
CZ    初中题库
```

三个题库通过不同的本地根目录隔离：

```text
E:\Desktop\题库中心\TEST\cms-v2
E:\Desktop\题库中心\GZ\cms-v2
E:\Desktop\题库中心\CZ\cms-v2
```

每个根目录下都有独立的：

- `cms-v2.db`
- `content-blocks/`
- `handouts/`
- `edit-sessions/`

### 2. 不新增领域实体

第一版不新增以下领域对象：

```text
QuestionBank
Bank
BankInstance
Tenant
Workspace
```

原因：

- 当前系统是本地个人工作系统，不是多人 SaaS。
- 题库选择发生在后端启动阶段，不发生在业务用例内部。
- 运行中不切换题库，业务 API 不携带 `{bankKey}`。
- 每个运行实例只面对一个当前题库根目录。

### 3. 领域模型保持不感知题库键

以下对象不增加 `BankKey` 或类似字段：

- `TeachingTopic`
- `Section`
- `SectionItem`
- `AtomicSection`
- `AtomicSectionPanel`
- `AtomicSectionItem`
- `SectionVariant`
- `ContentBlock`
- `ContentBlockVersion`
- `Handout`
- `HandoutVersion`
- `OutputTemplate`
- `OutputForm`
- `GeneratedFile`
- `Tag`
- `TagBinding`
- `TeachingNote`
- `TeachingNoteBinding`

数据隔离由不同根目录下的独立 `cms-v2.db` 和文件资产目录保证，而不是由同一个数据库中的 `BankKey` 字段保证。

### 4. 分层边界

当前题库信息应只出现在：

- API 配置读取。
- 依赖注入组合根。
- Infrastructure 的数据库路径与文件资产路径。
- Health 返回。
- 前端全局显示当前题库身份。

Application 用例和 Domain 实体继续只处理当前题库内的数据，不感知其他题库。

### 5. 第一版明确不做

- 不做跨题库查询。
- 不做跨题库复制或迁移。
- 不做运行时热切换。
- 不做题库级权限。
- 不做正式库危险操作保护。
- 不复用 V1 `/api/题库实例/{题库键}`。

### 6. 当前实现状态

截至 2026-06-25，当前题库上下文已经在 API / Infrastructure 运行时边界落地，但仍不进入领域模型：

- 运行时上下文为 `CmsV2CurrentBank(BankKey, DisplayName, Kind, RootDirectory)`。
- 配置解析和校验由 API 层 `CmsV2CurrentBankResolver` 完成。
- `DbContext` 与文件资产路径只接收当前题库根目录，不向 Application 用例或 Domain 实体传递 `BankKey`。
- Health 和前端全局顶部栏可以展示当前题库身份。
- `TeachingTopic / Section / ContentBlock / Handout` 等业务实体均未新增 `BankKey` 字段。
- 业务 API 路径保持 `/api/cms-v2/...`，没有 `{bankKey}` 路由段。

## 当前补充：SectionVariant 显式选择与新增 AS 同步语义

本节补充 SectionVariant 在 Section 后续持续编辑场景下的语义边界。

### 1. 显式选择模型保持不变

`SectionVariant` 仍然不是 `Section` 的完整复制，也不是实时镜像。它通过 `SectionVariantItem -> SectionItemId` 显式选择当前 Section 顶层内容。

```text
Section
  SectionItem -> AtomicSection
  SectionItem -> ContentBlock
  SectionVariant
    SectionVariantItem -> SectionItem
```

### 2. AtomicSection 的跟随边界

当 `SectionVariantItem` 选择了某个顶层 `SectionItem`，且该 `SectionItem.TargetType = AtomicSection` 时：

- Variant 选择的是整个 AS occurrence。
- 该 AS 内部后续新增、删除或移动 ContentBlock / panel 时，Variant 在展示和输出时按 AS 当前结构展开。
- 因此 AS 内部内容变化不需要新增 `SectionVariantItem`，也不触发 Variant 同步提示。

### 3. 新增顶层 AS 的同步边界

当 Section 后续新增一个顶层 `AtomicSection SectionItem` 时，已有 Variant 默认不会自动包含它。系统可以提供一个用户确认的同步用例，把该新 `SectionItem` 写入用户选择的 Variant。

该同步用例只创建新的 `SectionVariantItem`，不复制 `AtomicSection`、`ContentBlock`、DOCX、HTML 预览或任何文件资产。

### 4. 第一版不扩展模型

第一版不新增以下领域模型：

```text
SectionVariantSyncRule
SectionVariantAutoSyncPolicy
SectionVariantDiff
SectionVariantPendingChange
```

同步提示属于 Application / API / UI 工作流，不改变 `SectionVariant` 和 `SectionVariantItem` 的持久化语义。
