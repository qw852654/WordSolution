# CMS V2 标签系统与教学评注系统开发文档

本文档是 CMS V2 中 `Tag` 标签系统与 `TeachingNote` 教学评注系统的正式开发规格。它依据外部源规格 `E:/下载/CMS-V2-标签系统与教学评注系统开发文档.md` 校准，并纳入本仓库文档体系。

本文档最初用于定义目标口径；截至 Phase 10 收口，本文档同时记录当前实现状态、已知限制和人工验收点。

## 当前实现状态（Phase 10 收口）

已实现：

- 后端 `Tag / TagBinding` 已完成领域模型、EF 配置、迁移、仓储、Application 用例、API endpoint 和测试覆盖。
- 后端 `TeachingNote / TeachingNoteBinding` 已完成轻量评注新模型、EF 配置、迁移、仓储、Application 用例、API endpoint 和测试覆盖。
- `TagBinding` 第一版只允许 `ContentBlock / AtomicSection / Section`；从 `SectionItem / AtomicSectionItem` 入口编辑标签时，前端保存到底层 `ContentBlock`。
- `TeachingNoteBinding` 允许 `ContentBlock / Section / AtomicSection / AtomicSectionPanel / AtomicSectionItem / SectionItem` 六类目标；occurrence 入口绑定 occurrence 自身。
- `TeachingNote.EffectLevel` 可为 `null`；UI 未选择效果等级时保持 `null` 语义，不展示 `Unknown` 作为第一版可选项。
- `TeachingNote` 新契约不暴露旧任务流字段 `Title / Status / NextAction / SortOrder`，本表也不保存 `TargetType / TargetId`。
- V2 前端已完成标签基础组件、标签 Inspector 接入、`/content-blocks` 多标签 AND 筛选入口、教学评注基础组件、`SectionPage -> SectionInspector` 真实接入，以及当前对象评注 keyword / EffectLevel 筛选。

- 完整全局 TeachingNote 管理 / 搜索页。
- 主工作区评注数量轻提示、跨页面评注入口和复杂多对象绑定选择器。
- PDF / WordAndPdf 输出、变量替换、学生版 / 教师版条件过滤和旧数据迁移。

## 0. 总体定位

CMS V2 当前围绕以下结构组织内容：

```text
TeachingTopic
  -> Section
    -> SectionItem
      -> ContentBlock / AtomicSection

AtomicSection
  -> AtomicSectionPanel
    -> AtomicSectionItem
      -> ContentBlock

Handout
  -> HandoutVersion
    -> HandoutVersionItem
```

本轮新增两个互相独立的能力：

```text
Tag
  自由标签，用于检索、筛选和选题。

TeachingNote
  轻量教学评注，用于记录教学观察、课堂经验和复盘想法。
```

两者不能混用：

- `Tag` 表达“这个对象是什么、以后如何搜出来”。
- `TeachingNote` 表达“这个对象在教学中发生过什么、下次要注意什么”。

共同边界：

- 不修改 V1 后端。
- 不修改 V1 静态页面。
- 不修改 `VSTO/`。
- 不修改 `Word本地文件操作核心库/`。
- 所有新增后端能力只进入 `src-v2/WordSolution.CmsV2.*`。
- 所有浏览器前端能力只对接 `/api/cms-v2`。

## 1. Tag 标签系统

### 1.1 核心语义

`Tag` 是对内容资产或课程结构对象的自由标记。

标签用于回答：

```text
这道题考什么？
这个内容属于什么主题？
以后我怎么把它搜出来？
这个小节大概对应什么内容？
```

标签不是：

```text
教学评注
任务
待办
课堂记录
学生反馈
出现位置说明
板块角色
```

第一版采用接近 Notion 多选标签的体验，目标是快速标记、快速检索和快速筛选。

### 1.2 标签形态

第一版标签是自由标签。

不设计：

```text
TagKind
知识点 / 方法 / 模型 / 易错点 / 来源 分类
```

第一版标签没有层级。

不设计：

```text
ParentId
TagTree
标签树
知识点树
```

所有标签平铺使用。

### 1.3 标签名称规则

标签名在系统内全局唯一。

标准化规则：

```text
NormalizedName = Name.Trim()
```

比较规则：

- 首尾空格忽略。
- 英文字母大小写不敏感。
- 中文按原文比较。
- 中间空格保留。
- 不做同义词合并。
- 不做中文繁简转换。
- 不做复杂分词。

示例：

```text
"  机械能守恒  " = "机械能守恒"
"Energy" = "energy"
"机械 能 守恒" != "机械能守恒"
```

创建规则：

- 如果已有 Active 同名标签，创建接口返回已有标签。
- 如果只有 Archived 同名标签，返回业务错误，提示恢复或改名。
- 新建标签 `Name` 不能为空。

改名规则：

- 标签可以改名。
- 改名后 `Name` 不能为空。
- 改名后 `NormalizedName` 不能与其他标签重复。
- 改名后所有绑定位置显示新名称。

### 1.4 标签颜色规则

创建标签时，后端自动分配固定颜色 token，并写入 `Tag.Color`。

颜色 token 使用固定集合，第一版建议：

```text
tag-gray
tag-orange
tag-yellow
tag-green
tag-blue
tag-purple
tag-pink
tag-red
```

规则：

- 保存 token，不保存随意 hex。
- 同一个标签在所有位置显示同一个颜色。
- 第一版 UI 不提供手动改色入口。
- 前端根据 theme token 映射具体视觉样式。
- 不允许在业务组件中直接写死颜色值。

### 1.5 标签状态与归档

删除标签采用归档，不做物理删除。

```text
Tag.Status = Archived
```

状态规则：

```text
Active
  正常搜索、显示、绑定。

Archived
  不出现在普通打标签搜索候选中。
  不允许新绑定。
  已有绑定继续显示，但弱化。
  可恢复。
```

归档标签恢复规则：

- `Archived -> Active` 后重新出现在普通搜索候选中。
- 原有 `TagBinding` 仍然有效。
- 颜色保持不变。
- 名称保持不变。
- 恢复时如果与 Active 标签同名，必须报错并要求先改名。

### 1.6 标签绑定语义

标签优先绑定内容资产，不绑定出现位置。

第一版允许绑定：

```text
ContentBlock
AtomicSection
Section
```

第一版不绑定：

```text
SectionItem
AtomicSectionItem
AtomicSectionPanel
ContentBlockVersion
HandoutVersion
HandoutVersionItem
OutputForm
GeneratedFile
```

特殊入口规则：

```text
SectionItem 中显示的 ContentBlock 可以编辑标签，
但实际保存目标是 ContentBlock，不是 SectionItem。

AtomicSectionItem 中显示的 ContentBlock 可以编辑标签，
但实际保存目标是 ContentBlock，不是 AtomicSectionItem。
```

标签不自动继承：

- 给 `Section` 打标签，不会自动给其下所有 `ContentBlock` 打标签。
- 给 `AtomicSection` 打标签，不会自动给内部题目打标签。
- 不做父子自动复制。
- 不做隐式继承写库。

### 1.8 数据库约束与索引

目标表：

```text
Tags
TagBindings
```

关键约束：

```text
Tags.NormalizedName UNIQUE
TagBindings(TagId, TargetType, TargetId) UNIQUE
Tag.Name 非空
Tag.NormalizedName 非空
Tag.Color 非空
Tag.Status 合法
TagBinding.TagId 引用 Tags.Id
TagBinding.TargetId > 0
TagBinding.TargetType 合法
```

`TagBindings(TagId, TargetType, TargetId)` 唯一只表示“同一对象不能重复绑定同一标签”。

它不表示一个 Tag 只能绑定一个对象，也不限制一个对象绑定多个 Tag。

删除标签时第一版不物理删除 `Tag`，因此不因为归档标签而删除 `TagBinding`。

### 1.9 后端接口

#### 标签搜索

```http
GET /api/cms-v2/tags?keyword=xxx
```

行为：

- 只返回 Active 标签。
- 不返回 Archived 标签。
- 可按完全匹配、前缀匹配、包含匹配排序。

响应：

```ts
type TagDto = {
  id: number
  name: string
  color: string
  status: 'Active' | 'Archived'
  createdTime: string
  updatedTime: string
}
```

#### 创建标签

```http
POST /api/cms-v2/tags
```

请求：

```ts
type CreateTagRequest = {
  name: string
}
```

行为：

- Trim `name`。
- 生成 `NormalizedName`。
- 检查唯一性。
- 自动分配颜色 token。
- `Status = Active`。
- 已有 Active 同名标签时返回已有标签。
- 只有 Archived 同名标签时返回业务错误。

#### 更新标签

```http
PATCH /api/cms-v2/tags/{tagId}
```

第一版主要支持改名：

```ts
type UpdateTagRequest = {
  name?: string
}
```

颜色字段可由后端保留扩展能力，但第一版 UI 不提供改色入口。

#### 归档标签

```http
POST /api/cms-v2/tags/{tagId}/archive
```

行为：

- `Tag.Status = Archived`。
- 不删除 `TagBinding`。

#### 恢复标签

```http
POST /api/cms-v2/tags/{tagId}/restore
```

行为：

- 检查恢复后不与 Active 标签重名。
- `Tag.Status = Active`。

#### 获取对象标签

```http
GET /api/cms-v2/tag-bindings?targetType=ContentBlock&targetId=123
```

响应：

```ts
type TagBindingDto = {
  id: number
  tagId: number
  targetType: 'ContentBlock' | 'AtomicSection' | 'Section'
  targetId: number
  tag: TagDto
}
```

已有绑定可以返回 Archived 标签，用于弱化显示。

#### 设置对象标签

第一版优先实现替换式保存接口：

```http
PUT /api/cms-v2/tag-bindings
```

请求：

```ts
type SetTargetTagsRequest = {
  targetType: 'ContentBlock' | 'AtomicSection' | 'Section'
  targetId: number
  tagIds: number[]
}
```

行为：

- 针对单个目标对象替换它当前的标签列表。
- 只影响该目标对象的绑定。
- 不影响这些 Tag 与其他对象的绑定。
- 校验目标存在。
- 校验所有 Tag 存在且 Active。
- 删除当前对象已有绑定中不在 `tagIds` 的绑定。
- 新增 `tagIds` 中当前对象尚未绑定的绑定。
- 重复 `tagIds` 自动去重。

第一版不要求增量 add/remove 接口。

#### ContentBlock 标签筛选

第一版必须支持按标签筛选 `ContentBlock`。

建议接口：

```http
GET /api/cms-v2/content-blocks?tagIds=1&tagIds=2
```

或：

```http
POST /api/cms-v2/content-blocks/search
```

请求：

```ts
type SearchContentBlocksRequest = {
  keyword?: string
  tagIds?: number[]
  tagMatchMode?: 'All'
}
```

多标签逻辑固定为 AND：

```text
必须同时包含所有 tagIds。
```

普通标签搜索不提供 Archived tagId；如果筛选接口显式传入 Archived tagId，后端仍可按已有绑定返回结果。

### 1.10 前端交互

第一版优先入口是 Inspector。

#### TagMultiSelect

建议业务组件：

```text
TagMultiSelect
```

职责：

- 展示当前对象已有标签。
- 输入关键词搜索 Active 标签。
- 选择已有标签。
- 无完全匹配时快速新建标签。
- 新建后自动选中。
- 移除当前对象上的标签。
- 同一对象不允许重复选择。
- 已归档标签弱化显示。

边界：

- 组件只 emit 用户意图。
- API 调用归页面或 action composable。
- 颜色只使用 tag theme token。
- 不提供第一版改色入口。

#### 标签显示位置

第一版显示位置：

```text
Inspector
  显示和编辑标签。

ContentBlockCard / ContentBlockDisplay
  可显示少量标签，例如前 3 个，超出显示 +N。

搜索 / 筛选结果
  显示标签。

SectionTree
  不铺开显示全部标签。
```

`SectionTree` 主要承担结构导航，不展示全部标签；未来可显示“有标签”轻提示。

#### Archived 标签显示

已绑定的 Archived 标签继续显示，但弱化。

弱化视觉必须通过 theme token 表达，推荐：

```text
tooltip: 已归档
opacity / muted token
```

不要在组件中直接写死灰色或透明度常量。

## 2. TeachingNote 教学评注系统

当前实现状态：

- 后端模型闭环已完成：`TeachingNote`、`TeachingNoteBinding`、`TeachingNoteBindingTargetType`、`TeachingNoteEffectLevel`、仓储、Unit of Work、EF 配置和 `RebuildTeachingNotes` 迁移。
- Phase 6 已完成新的 TeachingNote Application 用例和 API endpoint，支持单条查询、统一搜索、按绑定对象查询、创建、更新和删除。
- 旧任务流字段 `Title / Status / NextAction / SortOrder / TargetType / TargetId` 不再作为当前模型契约。

### 2.1 核心语义

`TeachingNote` 是轻量教学注释系统，用于记录教学观察、课堂经验和复盘想法。

教学评注用于回答：

```text
这道题讲得怎么样？
这个板块安排得是否合理？
学生在哪里卡住？
这个小节下次讲要注意什么？
这道题作为例题是否合适？
这个课时节奏是否太快？
```

教学评注不是：

```text
标签
任务
待办
工单
状态流程
学生错题记录
作业系统
班级管理系统
```

### 2.2 与 Tag 的区别

```text
Tag
  标记内容是什么，用于检索和筛选。
  优先绑定 ContentBlock 本体。

TeachingNote
  记录教学观察、复盘经验、使用感受。
  可以绑定内容本体，也可以绑定出现位置。
```

示例：

```text
标签：机械能守恒
  表示这道题属于机械能守恒。

评注：这道题作为例题讲太跳，下次前面补一个基础过渡题。
  表示这道题在某个教学位置上的使用经验。
```

### 2.3 已取消字段

新模型不需要：

```text
Title
Status
NextAction
SortOrder
```

原因：

- 教学评注是一条注释，正文就是核心内容。
- 教学评注不是任务，不做状态流程。
- 下次怎么改直接写进 `Content`。
- 默认展示顺序按系统时间，不做手动排序。

`TeachingNote` 本表也不保存：

```text
TargetType
TargetId
```

目标绑定关系统一放到 `TeachingNoteBinding`。

### 2.4 保留字段

保留：

```text
NoteType
Content
EffectLevel?
OccurredAt?
CreatedTime
UpdatedTime
```

`NoteType` 是注释类型，不是任务类型。

建议第一版：

```text
General             普通记录
ClassroomRecord     课堂记录 / 课堂观察
LearningEffect      学习效果
TeachingReflection  教学反思
RevisionSuggestion  修改想法
QuestionReplacement 换题想法
CommonMistake       常见错误
```

`EffectLevel` 是可选教学效果感受，不是状态。

建议第一版：

```text
Good
Normal
Weak
Failed
Unknown
```

空值策略：

- 数据库/API 允许 `null`。
- UI 未选择时传 `null`。
- `Unknown` 枚举可以保留。
- 第一版 UI 不展示 `Unknown`，避免出现两个“未记录”。

`OccurredAt` 表示这条评注对应的实际发生时间，区别于系统创建时间 `CreatedTime`。

第一版不绑定学生、班级、作业。

public sealed class TeachingNoteBinding

#### TeachingNoteBindingTargetType

```csharp
public enum TeachingNoteBindingTargetType

    Section = 2,
    AtomicSection = 3,
    AtomicSectionPanel = 4,
    AtomicSectionItem = 5,

```

语义：

- `ContentBlock`：对内容本体的评注。

- `AtomicSectionPanel`：对板块整体的评注。
- `AtomicSectionItem`：对某个内容在 AtomicSection 中这一次出现的评注。
- `SectionItem`：对某个顶层内容在 Section 中这一次出现的评注。

### 2.6 数据库约束与删除

目标表：

```text
TeachingNotes
TeachingNoteBindings
```

关键约束：

```text
TeachingNotes.Content 非空
TeachingNotes.NoteType 合法
TeachingNotes.EffectLevel 可空；有值时必须合法
TeachingNoteBindings.TeachingNoteId 引用 TeachingNotes.Id
TeachingNoteBindings.TargetId > 0
TeachingNoteBindings.TargetType 合法
TeachingNoteBindings(TeachingNoteId, TargetType, TargetId) UNIQUE
```

删除评注采用物理删除：

- 删除 `TeachingNote`。
- 同时删除对应 `TeachingNoteBinding`。

当前 CMS V2 全局删除行为保持 `Restrict`，EF 仓储删除 `TeachingNote` 时先删除对应 Binding，再删除 Note。

旧 `TeachingNote` 迁移：

- 当前按“无真实业务数据”处理。
- 允许破坏性 migration 或重建表。
- 不做旧 `Title / Status / TargetType / TargetId` 兼容层。

### 2.7 后端接口

#### 查询某对象评注

```http
GET /api/cms-v2/teaching-note-bindings?targetType=AtomicSectionItem&targetId=123
```

返回所有绑定到该对象的评注，默认按 `UpdatedTime` 倒序。

也可以通过统一查询端点传入同样的 `targetType + targetId`：

```http
GET /api/cms-v2/teaching-notes?targetType=AtomicSectionItem&targetId=123
```

#### 查询单条评注

```http
GET /api/cms-v2/teaching-notes/{noteId}
```

不存在时返回 `404 ProblemDetails`。

#### 全局搜索评注

```http
GET /api/cms-v2/teaching-notes?keyword=太难&noteType=RevisionSuggestion&effectLevel=Weak
```

查询条件：

```ts
type SearchTeachingNotesQuery = {
  keyword?: string
  noteType?: TeachingNoteType
  effectLevel?: TeachingNoteEffectLevel
  targetType?: TeachingNoteBindingTargetType
  targetId?: number
  occurredFrom?: string
  occurredTo?: string
}
```

全文搜索范围是 `Content`。第一版可使用数据库 LIKE / Contains，不要求复杂全文索引。

默认排序为 `UpdatedTime desc`；同一时间再按 `Id desc` 保持稳定顺序。

#### 创建评注

```http
POST /api/cms-v2/teaching-notes
```

请求：

```ts
type CreateTeachingNoteRequest = {
  noteType: TeachingNoteType
  content: string
  effectLevel?: TeachingNoteEffectLevel | null
  occurredAt?: string | null
  bindings: Array<{
    targetType: TeachingNoteBindingTargetType
    targetId: number
  }>
}
```

规则：

- `content` 非空。
- `bindings` 至少一个。
- 所有绑定目标必须存在。
- `targetType` 只允许 `ContentBlock / Section / AtomicSection / AtomicSectionPanel / AtomicSectionItem / SectionItem`。
- 同一条评注中不能重复绑定同一对象。
- 未传 `effectLevel` 或传入 `null` 时保存为 `null`。

#### 更新评注

```http
PATCH /api/cms-v2/teaching-notes/{noteId}
```

请求：

```ts
type UpdateTeachingNoteRequest = {
  noteType?: TeachingNoteType
  content?: string
  effectLevel?: TeachingNoteEffectLevel | null
  occurredAt?: string | null
  bindings?: Array<{
    targetType: TeachingNoteBindingTargetType
    targetId: number
  }>
}
```

规则：

- 如果传 `bindings`，则替换该评注所有绑定。
- 如果不传 `bindings`，则保留原绑定。
- `content` 如果传入则不能为空。
- `effectLevel` 可以传入 `null`，表示清空教学效果记录。

#### 删除评注

```http
DELETE /api/cms-v2/teaching-notes/{noteId}
```

行为：

- 删除 `TeachingNoteBinding`。
- 删除 `TeachingNote`。

### 2.8 前端交互

第一版主要入口是 Inspector。

UI 创建评注时默认只绑定当前 Inspector 对象；API 和数据模型支持多绑定。

主界面最多显示轻提示：

```text
有 N 条评注
```

完整查看、创建、编辑、删除放在 Inspector。

建议组件：

```text
TeachingNoteList
TeachingNoteEditor
TeachingNoteCard
TeachingNoteBindingSummary
```

职责边界：

- `TeachingNoteList` 展示当前对象评注列表、空状态和加载状态。
- `TeachingNoteEditor` 负责编辑表单 UI，支持创建和更新，不直接调用 API。
- `TeachingNoteCard` 展示单条评注的类型、效果、发生时间、正文、关联对象摘要、更新时间和操作入口。
- `TeachingNoteBindingSummary` 展示一条评注还关联了哪些对象。
- 组件只 emit 用户意图。
- API 调用归页面或 action composable。

每条评注显示：

```text
NoteType
EffectLevel，可选
OccurredAt，可选
Content
关联对象摘要
UpdatedTime
编辑按钮
删除按钮
```

不显示：

```text
Title
Status
NextAction
SortOrder
```

删除交互：

- 前端必须二次确认。
- 提示“删除后不可恢复”。
- 多绑定评注删除时提示“会从所有关联对象中移除”。

## 5. Phase 10 人工验收清单

标签系统：

- 创建标签，并确认固定颜色 token 可显示。
- 重复创建同名 Active 标签时返回已有标签，不产生重复 Active 标签。
- 修改标签名称，确认重名改名被阻止。
- 通过后端 API 或基础控件能力修改颜色 token，确认只允许固定 token；当前真实工作台不提供完整标签改色入口。
- 归档标签后，普通搜索候选不再出现该标签。
- 已有 Archived 标签绑定仍可读，并在 Inspector、卡片或筛选结果中弱化显示。
- 搜索 Active 标签，确认候选不包含 Archived 标签。
- 给 `ContentBlock / AtomicSection / Section` 绑定标签，并确认同一目标不会重复绑定同一标签。
- 从 `SectionItem / AtomicSectionItem` occurrence 入口编辑内容标签时，确认保存到底层 `ContentBlock`。
- 在 `/content-blocks` 使用多个标签筛选，确认 `tagIds` 按 AND 语义查询。

教学评注系统：

- 分别为 `ContentBlock / Section / AtomicSection / AtomicSectionPanel / AtomicSectionItem / SectionItem` 创建、查看、编辑、删除评注。
- 确认 `SectionItem / AtomicSectionItem` occurrence 入口保存评注到 occurrence 自身，而不是底层 `ContentBlock`。
- 创建评注时不填写 `EffectLevel`，确认保存和返回为 `null`，UI 显示为未记录。
- 编辑 `NoteType / Content / EffectLevel / OccurredAt`，确认保存后按服务端结果刷新。
- 删除评注后，当前对象评注列表按当前筛选条件重新读取，空状态正确。
- 用 keyword 搜索评注正文。
- 用 `targetType + targetId` 查询当前对象评注。
- 用 `effectLevel` 筛选当前对象评注。
- 确认请求、响应、UI 均不出现旧任务流字段 `Title / Status / NextAction / SortOrder`。

跨模块回归：

- `SectionInspector` 中标签入口和教学评注入口目标解析不互相污染。
- `AtomicSectionPanel`、`SectionPage` 的选中对象切换后，标签和评注状态不残留到错误对象。
- `SectionPage`、`HandoutPage`、Word 输出链路保持既有行为；标签和教学评注不参与讲义输出内容。
