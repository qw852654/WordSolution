# CMS V2 后端数据模型开发文档

本文档记录 CMS V2 后端数据模型的目标对象、对象职责、字段、关系、约束、数据库表结构命名和分层落点。

当前已完成范围：

- V2 后端项目骨架。
- Domain 层领域对象、枚举、领域异常和最小领域规则。
- Infrastructure 层全新 EF Core 10 + SQLite 表结构、`CmsV2DbContext`、实体配置和初始建库迁移。
- Domain 层仓储契约与 `ICmsV2UnitOfWork`。
- Infrastructure 层 EF Core 仓储实现与 `EfCmsV2UnitOfWork`。
- Application 层用例、命令 DTO、应用异常和跨实体规则。

当前未完成范围：

- API Controller。
- 文件存储服务、DOCX 处理、HTML 预览、讲义生成。
- 前端。
- 旧数据迁移。

## 2. 数据库边界

V2 使用独立 SQLite 数据库：

```text
cms-v2.db
```

明确不做：

```text
不读取 question-bank.db
不修改 question-bank.db
不迁移旧业务数据
不建立旧 CMS 表结构兼容层
不实现旧数据导入工具
```

`CmsV2DatabasePaths.GetDatabasePath(bankRootDirectory)` 固定返回：

```text
{bankRootDirectory}/cms-v2.db
```

## 3. 全局建模原则

- 领域对象使用英文类名。
- 主键统一使用 `int Id`。
- SQLite 表主键为自增整数主键。
- 领域属性使用 `private set`。
- 公开构造函数负责建立最小有效状态。
- 为 EF materialization 保留私有无参构造函数。
- 核心对象默认只保存 `UpdatedTime`，不保存 `CreatedTime`。
- `GeneratedFile.GeneratedTime` 是业务事实，单独保留。
- `Difficulty` 只允许出现在 `ContentBlock`、`Section`、`SectionVariant`。
- `ContentBlockVersion` 不保存 `Difficulty`、`BlockType`、`QuestionType`。
- `TeachingNote` 独立建模，不归入 `ContentBlock`。
- 枚举在 EF Core 中按整数列存储。
- 删除行为默认使用 `Restrict`，避免误删内容资产。
- 多态引用只保存 `TargetType + TargetId`，不强行建立跨表外键。
- 跨聚合图递归循环检测留到 Application 阶段。

## 5. 对象、字段、关系与约束

### TeachingTopic

职责：表示教学内容在知识体系中的位置，只负责主题树定位，不承载讲义正文。

表名：`TeachingTopics`

字段：

```text
Id
ParentId
Name
Description
SortOrder
Status
UpdatedTime
```

关系与约束：

- `ParentId` 可指向另一个 `TeachingTopic`。
- `TeachingTopic 1 - N Section`。
- `TeachingNote` 可以挂载到 `TeachingTopic`。
- 删除行为 `Restrict`。

### Section

职责：表示某个教学主题下的一套小节上帝版本内容池。

表名：`Sections`

字段：

```text
Id
TeachingTopicId
Title
Description
Type
Difficulty
Status
SortOrder
UpdatedTime
```

关系与约束：

- `TeachingTopicId` 指向 `TeachingTopics.Id`。
- `Section 1 - N SectionItem`。
- `Section 1 - N SectionVariant`。
- `Difficulty` 保留在 `Section`。
- 删除行为 `Restrict`。

### SectionItem

职责：表示某个 `ContentBlock` 或 `AtomicSection` 被放入 `Section` 的一次出现。

表名：`SectionItems`

字段：

```text
Id
SectionId
TargetType
TargetId
ReferenceMode
LockedContentBlockVersionId
TitleOverride
ParentItemId
SortOrder
SelectionLayer
TeachingUseOverride
Status
Note
UpdatedTime
```

关系与约束：

- `SectionId` 指向 `Sections.Id`。
- `ParentItemId` 可指向同表 `SectionItems.Id`。
- `TargetType` 只允许 `ContentBlock` 或 `AtomicSection`。
- `TargetType + TargetId` 是多态引用，不建立跨表外键。
- `TargetType = ContentBlock` 时允许 `FollowLatest` 或 `LockedVersion`。
- `TargetType = AtomicSection` 时只能使用 `FollowLatest`，且不能设置 `LockedContentBlockVersionId`。
- `ReferenceMode = LockedVersion` 时必须提供 `LockedContentBlockVersionId`。
- `LockedContentBlockVersionId` 指向 `ContentBlockVersions.Id`。
- `SectionItem` 不保存 `Difficulty`。
- 删除行为 `Restrict`。

### AtomicSection

职责：表示 Section 内部的最小讲解结构。它组织内容块，但自身不保存 DOCX 正文。

表名：`AtomicSections`

字段：

```text
Id
Title
Description
Type
Status
UpdatedTime
```

关系与约束：

- `AtomicSection` 只能通过 `SectionItem` 放入 `Section`。
- `AtomicSection` 内部只能放 `ContentBlock`。
- `AtomicSection` 不能被 `HandoutVersionItem` 直接引用。
- `AtomicSection` 不保存 `Difficulty`。

### AtomicSectionItem

职责：表示 `ContentBlock` 被放入 `AtomicSection` 的一次出现。

表名：`AtomicSectionItems`

字段：

```text

LockedContentBlockVersionId
```

关系与约束：

- `AtomicSectionId` 指向 `AtomicSections.Id`。
- `ContentBlockId` 指向 `ContentBlocks.Id`。
- 只能引用 `ContentBlock`，不提供 `AtomicSection` 目标入口。
- `ReferenceMode = LockedVersion` 时必须提供 `LockedContentBlockVersionId`。
- `LockedContentBlockVersionId` 指向 `ContentBlockVersions.Id`。
- 删除行为 `Restrict`。

- `Difficulty` 保留在 `SectionVariant`。

### SectionVariantItem

### ContentBlockVersion

- `ContentBlockId + VersionNumber` 唯一。
- 不保存 `Difficulty`。
- 不保存 `BlockType`。
- 不保存 `QuestionType`。
- 正文主来源是 `DocxPath` 指向的 DOCX 文件。
- `PlainText` 用于搜索和索引。

### Infrastructure 实现约束

```text
EfRepository<TEntity>
  基础 GetById / List / Add / Update / Remove。
  GetById 和 List 默认 AsNoTracking。
  List 默认按 Id 排序。

Ef*Repository
  实现 17 个专用仓储。
  专用查询默认 AsNoTracking。
  有 SortOrder 的编排查询按 SortOrder + Id 排序。
  多态引用查询按 TargetType + TargetId 过滤。

EfCmsV2UnitOfWork
  所有仓储共享同一个 CmsV2DbContext。
  SaveChangesAsync 统一提交。
  ExecuteInTransactionAsync 使用同一个 DbContext 事务。
  成功时保存并提交，异常时事务回滚。
```

仓储阶段未新增数据库表、未新增迁移、未注册 API DI。

## 8. Application 用例与跨实体规则

### 公共类型

```text
CmsV2ApplicationException
  应用层业务校验异常。

CreatedEntityResult
  创建类用例统一返回 Id。
```

### 内容块用例

```text
ContentBlockUseCases.CreateContentBlockWithInitialVersionAsync
  创建 ContentBlock。
  创建 v1 ContentBlockVersion。
  将 ContentBlock.CurrentVersionId 设置为 v1。
  将 v1 标记为 IsCurrent。

ContentBlockUseCases.CreateContentBlockVersionAsync
  按同一 ContentBlock 下现有最大 VersionNumber + 1 创建版本。
  可选择立即设为当前版本。

ContentBlockUseCases.SetCurrentContentBlockVersionAsync
  校验版本存在且属于指定 ContentBlock。
  将目标版本标记为当前版本。
  将同一 ContentBlock 的其他版本标记为非当前版本。
  更新 ContentBlock.CurrentVersionId。
```

Domain 为支持该用例新增最小行为方法：

```text
ContentBlock.SetCurrentVersion
ContentBlockVersion.MarkCurrent
ContentBlockVersion.MarkNotCurrent
```

### 组合关系用例

```text
ContentBlockRelationUseCases.AddContentBlockRelationAsync
  校验 ParentBlock 与 ChildBlock 存在。
  校验 LockedContentBlockVersionId 属于 ChildBlock。
  禁止 ParentBlockId = ChildBlockId。
  从 ChildBlock 开始沿 ContentBlockRelations children 做 DFS。
  如果 DFS 能到达 ParentBlock，则拒绝新增，避免递归循环。
```

### 小节与 AtomicSection 编排用例

```text
SectionUseCases.AddSectionItemAsync
  校验 Section 存在。
  TargetType = ContentBlock 时校验 ContentBlock 存在。
  ContentBlock 锁定版本必须属于对应 ContentBlock。
  TargetType = AtomicSection 时校验 AtomicSection 存在。
  AtomicSection 引用不允许锁定 ContentBlock 版本。

AtomicSectionUseCases.AddAtomicSectionItemAsync
  校验 AtomicSection 存在。
  校验 ContentBlock 存在。
  锁定版本必须属于对应 ContentBlock。
```

### SectionVariant 与 Handout 编排用例

```text
SectionVariantUseCases.CreateSectionVariantAsync
  校验 Section 存在后创建 SectionVariant。

SectionVariantUseCases.AddSectionVariantItemAsync
  校验 SectionVariant 存在。
  校验 SectionItem 存在。
  SectionItem 必须属于该 SectionVariant 的 Section。

HandoutUseCases.CreateHandoutVersionAsync
  校验 Handout 存在后创建 HandoutVersion。

HandoutUseCases.AddHandoutVersionItemAsync
  校验 HandoutVersion 存在。
  TargetType 只允许 SectionVariant 或 ContentBlock。
  拒绝直接引用 Section / AtomicSection。
  校验目标 SectionVariant 或 ContentBlock 存在。
```

本阶段未新增 API Controller、未新增 DI 注册、未新增数据库表、未新增迁移、未实现 DOCX/HTML 预览/生成链路。
