# CMS V2 前端国际化规则

CMS V2 前端默认界面语言使用 `zh-CN`。即使第一版只有一个语言，也必须从一开始使用 Vue I18n。

## 1. 基本要求

所有可见 UI 文本必须使用 i18n key。

禁止：

```vue
<Button>Save</Button>
```

必须：

```vue
<Button>{{ t("common.save") }}</Button>
```

说明：

- 默认 locale 为 `zh-CN`。
- 可以保留 `en` 资源作为 fallback 或后续切换基础，但当前默认界面不使用英文说明文案。
- 第一版不要求语言切换 UI。
- 架构必须支持未来切换语言。

## 1.1 英文术语保留规则

默认界面虽然使用中文，但以下名称在 UI 中也保留英文，不翻译成中文：

```text
ContentBlock
ContentBlockCard
ContentBlockDisplay
Section
SectionPage
SectionItem
SectionVariant
AtomicSection
FocusTree
ComponentLab
Mock Data
DTO
API
Pinia
Vue Router
Vue I18n
```

规则：

- 组件名、领域对象名、DTO 名、路由名保持英文。
- 解释性文本、按钮、状态、提示、空状态、错误信息必须显示中文。
- 示例：`ComponentLab` 标题可保留英文，但说明文字应为“可复用 UI 组件必须先在这里用 Mock Data 验收，再进入真实页面。”
- 示例：`ContentBlockCard` 标题可保留英文，但说明文字必须中文。

## 2. 目录建议

```text
src/
  app/
    i18n.ts
  locales/
    en.ts
    zh-CN.ts
```

当前至少实现：

```text
src/locales/zh-CN.ts
src/locales/en.ts
```

其中 `zh-CN.ts` 是默认界面文案来源，`en.ts` 是 fallback 和未来语言切换基础。

## 3. Key 命名规则

推荐按领域和页面分组：

```text
common.save
common.cancel
common.delete
common.loading
common.empty

navigation.topics
navigation.sections
navigation.handouts
navigation.contentBlocks

contentBlock.title
contentBlock.status
contentBlock.currentVersion
tag.title
tag.search
tag.create
tag.archive
tag.restore
tag.color

section.pageTitle
section.addItem
section.structure
section.inspector

handout.generateWord
output.generatedFiles
teachingNote.title
teachingNote.search
teachingNote.filter
teachingNote.effectLevel.*
teachingNote.noteType.*
teachingNote.targetType.*

shell.bank.loading
shell.bank.unavailable
shell.bank.kind.test
shell.bank.kind.production
```

规则：

- key 使用小驼峰。
- 不在 key 中写完整英文句子。
- 页面专属文案放页面命名空间。
- 通用操作放 `common`。

## 3.1 AppShell 当前题库文案

`AppShell` 顶部栏需要显示后端 `GET /api/cms-v2/health` 返回的当前题库身份。

显示规则：

- 加载中使用 `shell.bank.loading`。
- health 读取失败使用 `shell.bank.unavailable`，不阻塞页面继续使用。
- 读取成功后显示 `{bankDisplayName} · {bankKey}`。
- `bankKind = Test` 使用 `shell.bank.kind.test`。
- `bankKind = Production` 使用 `shell.bank.kind.production`。
- 其他未知 `bankKind` 可以回退显示后端原始字符串。

该区域只用于识别当前后端绑定的题库，不提供运行时切换入口。

## 4. 组件文案规则

Presentation component：

```text
优先接收已翻译文本。
如果组件内部有固定通用文案，使用 common.* key。
```

Business component：

```text
可以直接使用业务命名空间 key。
```

Page：

```text
负责页面标题、空状态、错误提示、主要操作文案。
```

## 5. 错误信息

后端返回 ProblemDetails 时，前端处理原则：

```text
后端 detail 可作为调试信息或兜底显示。
用户可见固定错误文案优先使用 i18n key。
```

示例：

```text
api.error.validation
api.error.notFound
api.error.server
api.error.network
```

## 6. 不需要立即实现的内容

第一版不需要：

- 语言切换按钮。
- 自动检测浏览器语言。
- 多语言内容编辑。
- 后端本地化错误码体系。

但不要写死英文文本，以免后续迁移成本变高。
