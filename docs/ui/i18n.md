# CMS V2 前端国际化规则

CMS V2 前端第一版使用英文 UI 文案，后续补充中文。即使第一版只有英文，也必须从一开始使用 Vue I18n。

## 1. 基本要求

所有可见 UI 文本必须使用 i18n key。

禁止：

```vue
<Button>Save</Button>
```

必须：

```vue
<Button>{{ t("common.save") }}</Button>
```

说明：

- 第一版只要求英文资源。
- 中文资源后续补充。
- 第一版不要求语言切换 UI。
- 架构必须支持未来切换语言。

## 2. 目录建议

```text
src/
  app/
    i18n.ts
  locales/
    en.ts
    zh-CN.ts
```

第一版可只实现：

```text
src/locales/en.ts
```

但 `i18n.ts` 应允许后续注册 `zh-CN`。

## 3. Key 命名规则

推荐按领域和页面分组：

```text
common.save
common.cancel
common.delete
common.loading
common.empty

navigation.topics
navigation.sections
navigation.handouts
navigation.contentBlocks

contentBlock.title
contentBlock.status
contentBlock.currentVersion

section.pageTitle
section.addItem
section.structure
section.inspector

handout.generateWord
output.generatedFiles
teachingNote.title
```

规则：

- key 使用小驼峰。
- 不在 key 中写完整英文句子。
- 页面专属文案放页面命名空间。
- 通用操作放 `common`。

## 4. 组件文案规则

Presentation component：

```text
优先接收已翻译文本。
如果组件内部有固定通用文案，使用 common.* key。
```

Business component：

```text
可以直接使用业务命名空间 key。
```

Page：

```text
负责页面标题、空状态、错误提示、主要操作文案。
```

## 5. 错误信息

后端返回 ProblemDetails 时，前端处理原则：

```text
后端 detail 可作为调试信息或兜底显示。
用户可见固定错误文案优先使用 i18n key。
```

示例：

```text
api.error.validation
api.error.notFound
api.error.server
api.error.network
```

## 6. 不需要立即实现的内容

第一版不需要：

- 语言切换按钮。
- 自动检测浏览器语言。
- 多语言内容编辑。
- 后端本地化错误码体系。

但不要写死英文文本，以免后续迁移成本变高。
