# 内容管理系统升级路线

## 当前共识

本仓库当前主线已经切换到 CMS V2。

明确结论：

- 第一版前端已经废弃。
- 第一版后端已经废弃。
- 新前端只能对接 V2 后端。
- 旧静态页面、旧接口和旧页面结构只作为历史参考，不再继续演进。

## 系统定位

系统目标是：

> 面向高中物理教学的本地讲义内容管理与编排系统。

核心工作流：

1. 管理可复用内容块。
2. 组织 AtomicSection、Section、SectionVariant。
3. 组织 Handout、HandoutVersion、OutputForm。
4. 在浏览器中完成结构编排。
5. 在 Word 中完成精细编辑与最终输出。

## 当前待补齐阶段：SectionVariant 创建与选择模型

本阶段为文档已确认、实现待补齐的 SectionPage 能力，不表示当前已经完成。

目标：

- 在 `SectionPage` 中通过 `SectionTree` 的 `Section` 根节点右键菜单创建 `SectionVariant`。
- 使用两步创建流程：先填写 `SectionVariant` 元数据，再进入当前 `Section` 的内容选择模式。
- 默认选择由后端根据目标顶层 `SectionItem` 的难度计算，前端只展示和提交用户最终勾选结果。
- 后端以一次事务创建 `SectionVariant` 和对应 `SectionVariantItem`，不允许前端循环调用多个新增 item API。

第一版范围：

- 唯一入口：`SectionPage -> SectionTree -> Section 根节点右键菜单 -> 新建 SectionVariant`。
- 只选择顶层 `SectionItem`，顶层定义为 `SectionItem.ParentItemId == null`。
- `SectionVariantItem` 只保存对 `SectionItemId` 的引用，不复制 `ContentBlock`、`AtomicSection`、`CompositeBlock` 或正文结构。
- `CompositeBlock` 仍然只是 `ContentBlock.BlockType` 为组类型时的前端展示方式，不新增后端目标类型。
- 允许创建空 `SectionVariant`。
- 创建成功后刷新 `SectionTree` / Variant 列表，但不自动打开或选中新建 Variant。

后续预留：

- `AtomicSection` 内部部分选择能力。
- 根据难度和教学用途给出同步建议。
- `Section` 变化后对已有 `SectionVariant` 的差异提示。
- `SectionVariant` 复制、归档、重命名等管理能力。

当前明确不做：

- 不从 Toolbar、Workspace、Inspector 或 TeachingStructureTree 创建 `SectionVariant`。
- 不在第一版选择 `AtomicSectionItem` 或 `CompositeBlock` 子 relation。
- 不把 `SectionVariant` 做成独立页面主线。
- 不把 `SectionVariant` 写成新的结构树节点领域模型。
## 当前补充阶段：AS AtomicSection 板块化题目演化工作流

本阶段用于收口 `AtomicSection` 内部的板块化题目演化能力，属于 `SectionPage` 上线前的独立大块。它不改变 V1，不修改 VSTO，不触碰 `Word本地文件操作核心库`。

### 已确认口径

- `AtomicSection` 表示一个讲解最小单元。
- `AtomicSection` 内部需要按教学职责和难度组织内容，而不是只把 `ContentBlock` 顺序平铺。
- 新增目标实体 `AtomicSectionPanel`，用于表示 `AtomicSection` 内的知识点、例题、变式题、练习题、课后练习等板块。
- 新增枚举 `AtomicSectionTeachingRole`：`Unclassified`、`Knowledge`、`Example`、`Variant`、`Practice`、`Homework`。
- `AtomicSectionItem` 需要增加 `AtomicSectionPanelId` 和 `TeachingRole`。
- `ContentBlock` 不记录自己属于哪个 `AtomicSection` 或哪个 `AtomicSectionPanel`；归属关系只能由引用关系表达。
- `ContentBlock.Difficulty` 是内容资产自身难度；`AtomicSectionPanel.Difficulty` 是板块匹配规则。
- `CompositeBlock` 仍然是 `ContentBlock.BlockType` 的一种表现，不新增独立后端 target type。
- 当前数据库均为模拟数据，可以废弃重建，因此本阶段不做旧数据迁移、不做兼容补丁。

### 阶段拆分

```text
AS-1 文档校准
AS-2 Domain / Persistence 补齐
AS-3 Application / API 补齐
AS-4 后端测试与种子数据校准
AS-5 ComponentLab 验收 AtomicSectionPanel UI
AS-6 SectionPage 接入 AtomicSectionPanel 工作流
AS-7 Handout 生成顺序回归
AS-8 上线前验收修补
```

### AS-1：文档校准

只更新开发文档，明确目标模型、前后端边界、初始化规则、API 计划和测试口径。

本阶段禁止：

- 修改后端代码。
- 修改前端代码。
- 新增数据库迁移。
- 生成或迁移旧数据。

### AS-2：Domain / Persistence 补齐

目标：

- 新增 `AtomicSectionPanel` 领域模型和持久化表。
- 扩展 `AtomicSectionItem` 的 `AtomicSectionPanelId`、`TeachingRole`。
- 为 `(AtomicSectionId, TeachingRole, Difficulty)` 建立唯一约束。
- 建立 `AtomicSectionPanel` 的仓储和 UnitOfWork 入口。

边界：

- 不做旧数据迁移。
- 不自动创建旧数据兼容项。
- 不在 `ContentBlock` 上增加归属字段。

### AS-3：Application / API 补齐

目标：

- 创建、重命名、修改、移动、删除 `AtomicSectionPanel`。
- 在 `AtomicSection` 内创建内容时按 panel 上下文写入 `AtomicSectionItem`。
- 支持更新 `AtomicSectionItem` 的教学角色和难度匹配。
- 根据角色和难度执行自动归组。

### AS-4：后端测试与种子数据校准

目标：

- 覆盖领域规则、唯一约束、自动归组、删除 panel、移动顺序、wrap-as-AS 等测试。
- 需要演示数据时直接重建当前测试库，不考虑旧数据迁移。

### AS-5：ComponentLab 验收

目标：

- 新增并验收 `AtomicSectionPanelBlock`。
- 新增并验收 `AtomicSectionUnassignedArea`。
- 更新 `AtomicSectionBlock` 作为 panel 和未归组区的外层装配组件。

### AS-6：SectionPage 接入

目标：

- `Workspace` 中 `AtomicSection` 展示 panel 区、panel 内 item、未归组区。
- `SectionTree` 显示 panel 节点和未归组节点。
- `Inspector` 支持 panel 和 item 分类详情。
- 所有写操作通过页面级 action 调用 API，组件本身只 emit 事件。

### AS-7：Handout 生成顺序回归

目标：

- `Handout` 展开 `AtomicSection` 时先按 panel 排序，再按 item 排序，最后输出未归组内容。
- 第一版不输出 panel 标题。

### AS-8：上线前验收修补

目标：

- 修补 UI 信息密度、空 panel 展示、插入点上下文、错误提示和生成 Word 回归问题。
