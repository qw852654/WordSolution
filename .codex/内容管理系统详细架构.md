# 内容管理系统详细架构

## 1. 当前架构结论

本仓库当前主线已经切换到 CMS V2。

明确结论：

- 第一版前端已经废弃。
- 第一版后端已经废弃。
- 新前端只能对接 CMS V2 后端。
- V1 页面、V1 接口、V1 静态资源只作为历史参考，不再作为当前架构基础。

当前全局阶段 1 只做文档清理：

- 不创建前端工程
- 不修改 `VSTO/`
- 不修改 `Word本地文件操作核心库/`
- 不修改 V1 后端业务代码与项目文件

当前系统是：

> 面向高中物理教学的本地讲义内容管理与编排系统。

它不是：

- 普通题库 CRUD 后台
- 多人 SaaS 系统
- 在旧静态页面上持续修补的网页集合

## 2. 当前主线工程结构

当前主线工程：

- `src-v2/WordSolution.CmsV2.Domain`

- `src-v2/WordSolution.CmsV2.Api`
- `src-v2/WordSolution.CmsV2.Tests`

历史保留工程：

- `题库核心`
- `题库应用`
- `题库基础设施`
- `题库本地服务`
- `题库本地服务/wwwroot`

- `VSTO`
- `Word本地文件操作核心库`
- `Core.QuestionBank`
- `TagRunner`
- `tools/旧题库迁移工具`

## 3. 当前依赖方向

```text
V2 Frontend
  -> WordSolution.CmsV2.Api
      -> WordSolution.CmsV2.Application
          -> WordSolution.CmsV2.Domain

WordSolution.CmsV2.Infrastructure
  -> WordSolution.CmsV2.Domain

WordSolution.CmsV2.Api
  -> WordSolution.CmsV2.Application
  -> WordSolution.CmsV2.Infrastructure
```

约束：

- `Application` 不直接依赖 `Infrastructure`
- `Domain` 不依赖任何上层
- 新前端不直接接数据库、不直接碰文件资产

## 4. 系统核心对象

### 4.1 TeachingTopic

表示教学内容在知识结构中的定位。

示例：

```text
功能关系
机械能守恒
竖直圆轨道
杆模型
球模型
```

职责：

- 提供教学主题定位
- 承载浏览器工作台导航语义

不承载：

- 内容块版本
- 讲义版本
- 生成记录

### 4.2 ContentBlock

可复用内容资产，主资产以 `.docx` 保存。

常见类型：

- 知识点
- 例题
- 练习
- 方法总结
- 普通说明
- 组合型内容块

### 4.3 AtomicSection

小的教学组织片段，用于承接多个内容块的局部编排。

### 4.4 Section

回答的问题是：

> 这个教学主题应该怎么讲？

### 4.5 SectionVariant

同一个 Section 的不同教学用途变体。

例如：

- 基础讲解版
- 提高班版
- 一轮复习版

SectionVariant 从 Section 这个完整知识池中选择内容，不是 Section 本体，也不是“上帝版本”。

SectionVariant 自身有 `Difficulty`，并与 `Section`、`AtomicSection`、`ContentBlock` 共用同一套难度系统：

```text
Unset / Basic / Medium / Advanced / Top
```

第一版创建 SectionVariant 时，用户先选择 Difficulty，系统默认选入同一 Section 下难度小于等于该 Difficulty 的顶层 SectionItem；`Unset` 不自动选入。顶层 ContentBlock / CompositeBlock 按 ContentBlock 难度判断，顶层 AtomicSection 按 AtomicSection 难度判断整个 as。后续完整模型需要支持 AtomicSection 内部按 AtomicSectionItem 部分选择，但第一版只做顶层 SectionItem 选择。

### 4.6 Handout

回答的问题是：

> 这份材料属于哪类输出对象？

### 4.7 HandoutVersion

回答的问题是：

> 这份讲义当前要按什么结构输出？

### 4.8 OutputForm / OutputTemplate / GeneratedFile

用于输出编排、模板套用和最终生成记录。

### 4.9 TeachingNote

用于承载教学备注、修订建议和讲解提醒。

## 5. 当前 V2 数据与文件边界

### 5.1 数据库

V2 主数据库：

```text
cms-v2.db
```

明确约束：

- 不读取 `question-bank.db`
- 不修改 `question-bank.db`
- 不为旧数据库做兼容层

### 5.2 文件资产

当前 V2 文件资产围绕内容块和讲义输出组织。

典型结构：

```text
{bankRootDirectory}
  cms-v2.db
  content-blocks/
    source/{ContentBlockId}/v{VersionNumber}.docx
    html/{ContentBlockId}/v{VersionNumber}.html
    text/{ContentBlockId}/v{VersionNumber}.txt
  handouts/
    generated/{HandoutVersionId}/*.docx
```

## 6. 当前 API 边界

当前新前端的唯一后端边界是：

```text
/api/cms-v2
```

例如：

- `/api/cms-v2/teaching-topics`
- `/api/cms-v2/content-blocks`
- `/api/cms-v2/sections`
- `/api/cms-v2/atomic-sections`
- `/api/cms-v2/section-variants`
- `/api/cms-v2/handouts`
- `/api/cms-v2/output-forms`

禁止再作为当前前端目标的接口：

- `/api/题库实例/...`

## 7. 当前前端架构边界

新前端必须：

1. 作为独立 V2 工程重建。
2. 不继续基于 `题库本地服务/wwwroot` 的 V1 静态页面演进。
3. 不兼容 V1 前端 API 形状。
4. 不继续使用 `cms.html`、`sections.html`、`handouts.html`、`references.html` 作为当前页面入口目标。

## 8. 当前页面模式

### 8.1 TeachingTopic Workspace

用于选择工作对象，而不是直接编辑内容正文。

布局原则：

- 左侧：教学主题导航
- 中间：主题工作台
- 右侧：无常驻详情面板

### 8.2 SectionPage

用于编排 Section / SectionVariant。

布局原则：

- 左侧：结构树
- 中间：工作区
- 右侧：选中对象检查面板

### 8.3 HandoutPage

用于编排 Handout / HandoutVersion / OutputForm。

布局原则：

- 左侧：结构树
- 中间：工作区
- 右侧：检查面板 / 输出信息

## 9. 当前开发原则

### 9.1 前端

- 先从项目结构开始
- 先建立 labs / mocks / apis / pages / components
- 先做 V2-only 文档与组件约定
- 再做具体页面

### 9.2 后端

- 继续以 `src-v2` 为唯一后端主线
- API 继续围绕 `/api/cms-v2`
- 不回头补 V1 兼容接口给新前端使用

## 10. 历史遗留内容如何看待

仓库中仍可能存在以下残留：

- `题库本地服务/wwwroot`
- `cms.html`
- `sections.html`
- `handouts.html`
- `references.html`
- `/api/题库实例/...`
- `question-bank.db`

这些内容的统一定位是：

- 历史参考
- 行为回顾
- 非当前主线

如果后续任务涉及新前端开发，应优先忽略这些旧入口，除非任务明确要求迁移历史逻辑。
