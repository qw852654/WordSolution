# 主线开发说明

## 当前主线结论

本仓库当前主线已经切换到 CMS V2。

明确约束：

- 第一版前端已经废弃。
- 第一版后端已经废弃。
- 新前端只能对接 V2 后端。
- 旧静态页面、旧接口、旧开发口径只作为历史参考，不再作为当前实现依据。

## 当前主线项目

当前开发默认进入：

- `src-v2/WordSolution.CmsV2.Domain`
- `src-v2/WordSolution.CmsV2.Application`
- `src-v2/WordSolution.CmsV2.Infrastructure`
- `src-v2/WordSolution.CmsV2.Api`
- `src-v2/WordSolution.CmsV2.Tests`
- 经确认后新增的 V2 前端项目目录

## 当前非主线项目

以下内容保留，但默认不再承接新主线需求：

- `题库核心`
- `题库应用`
- `题库基础设施`
- `题库本地服务`
- `题库本地服务/wwwroot`
- `question-bank-office-addin`
- `VSTO`
- `Word本地文件操作核心库`
- `Core.QuestionBank`
- `TagRunner`
- `tools/旧题库迁移工具`

## 当前构建入口

CMS V2 后端主线：

```powershell
dotnet build WordSolution.CmsV2.sln -v:minimal
```

说明：

- 新前端项目尚未正式创建。
- 后续前端应建立自己的独立工程与构建入口。

## 当前前后端边界

前端与后端的唯一有效边界是：

```text
V2 Frontend
  -> /api/cms-v2
  -> WordSolution.CmsV2.Api
```

禁止继续作为新实现目标的内容：

- `cms.html`
- `sections.html`
- `handouts.html`
- `references.html`
- `/api/题库实例/...`
- `question-bank.db`
- `题库本地服务/wwwroot` 里的 V1 页面增量演进

## 当前开发阶段判断

当前可以视为：

1. V2 后端项目结构已经建立。
2. V2 后端基础模型、持久化、应用用例和 API 已经有第一版。
3. V2 前端决定重写，不再沿用第一版前端。
4. 当前前端任务的正确起点是“先清理文档口径，再从项目结构开始建设新前端工程”。

## 当前阶段定义

当前采用的简化阶段是：

1. 文档清理
2. V2 前端项目结构
3. 前端基础骨架
4. SectionPage
5. HandoutPage
6. 内容块与详情工作流
7. 高级能力

当前正在执行：

```text
阶段 1：文档清理
```

当前阶段 1 边界：

- 只清理 V1 前端 / V1 后端相关文档与开发要求
- 不创建前端工程
- 不修改 `VSTO/`
- 不修改 `Word本地文件操作核心库/`
- 不修改 V1 后端业务代码与项目文件
- 不修改 `题库本地服务/wwwroot` 下的旧页面代码

## 当前推荐顺序

建议按以下顺序推进：

1. 清理 V1 前端 / 旧后端相关文档与开发要求。
2. 明确 V2 前端项目结构与目录。
3. 建立独立前端工程底座。
4. 建立组件实验页、mock 数据和基础 UI 约定。
5. 再开始 SectionPage、HandoutPage 等具体页面开发。

## 当前差异说明

仓库里仍然保留大量 V1 页面、V1 接口说明和旧阶段记录。

这些内容的定位是：

- 可以帮助理解历史设计；
- 可以帮助比对旧行为；
- 不能继续作为当前实现依据。

如果后续文档仍出现 V1 页面入口或 `/api/题库实例/...`，应优先视为待清理的历史残留。
